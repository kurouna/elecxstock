# ニュース（設計・案 v5）

マーケットのタブに、投資に関わるニュースの見出しを時刻順に並べるペイン（`news`）を足す。見出しは同梱した RSS の一覧（登録表）から取り、
利用者は URL を打たない。設定で丸ごと切れて、切ればニュースのための通信は一切しない（オフラインで動くことは変えない）。
**普通の RSS リーダーと同じく、見出しを表示するだけ**。翻訳の機能は持たない（§6）。

- モック: [mock/news.html](mock/news.html)（`file://` で開ける）
- 候補のフィード: [news-feeds.md](news-feeds.md)
- 参考: 取得と RSS の読み取りは elecdex（`src/main/feeds/`）
- 状態: v6・実装済み（2026-11-17）。要求は requirements.md §6.19（`FR-NW1〜NW9`）。経緯は §13、実装で設計から変えた点は §14

## 1. 方針

- **見出しとリンクだけ**。本文・画像は取らない・出さない。要約（RSS の description）は登録表で許したフィードだけ、文字で出す。
  画像を出すと任意の CDN を許可リストと CSP（`img-src`）に足すことになり、通信先を説明できなくなる。
- **表示するだけ。訳さない・作り変えない**。見出しは配信元の文のまま出す。ほかの言語で読みたい人は、見出しをコピーして（§7.4）
  自分の意志で別のアプリで訳す。
- **通信先は同梱の登録表だけ**。利用者が URL を足す操作は持たない。ニュースの要求は専用の fetch で、**オンのフィードのホストだけ**へ出す。
- **利用者が答えるまで通信しない**。新しく入れた人は初回起動で選ぶ（選択の初期値は「取る」）。既存の利用者は、更新しても答えるまで取らない。
  管理者はポリシーで一括して止められる（§3.2）。
- **言語で分ける**。各フィードは `lang` を持ち、既定でオンにするのは表示言語の分だけ。もう一方の言語も個別にオンにできる。
  英語の Bloomberg は日本語の表示でも既定でオン（§2.1）。
- **既存のコードと疎結合**。ニュースのコードは `news/` のフォルダに閉じ、既存のファイルへの差し込みは §11 の一覧の箇所だけ。
  登録表は JSON。ニュースの設定・キャッシュは `data/news/` に閉じる。ニュースを外すときは、フォルダと差し込みの行を消せば元に戻る。
- **動きは出さない**。回る印・点滅・スライドは使わない。新しい見出しは文字の帯で知らせる。

## 2. 登録表（`resources/news/feeds.json`）

フィードはコードに書かず **JSON** で持つ。フィードを足す・外す・直すのは JSON だけで済む。

- **asar に入れる**: リポジトリの `resources/news/feeds.json` を、ビルドで `core.js` に取り込む（`import feeds from '…/feeds.json'`）。
  インストーラに入り、`enableEmbeddedAsarIntegrityValidation`（NFR-S3）の対象になる。
  - `extraResources`（asar の外）には置かない。登録表は許可リストと「記事を開いてよいか」のもとなので、利用者ごとのインストール
    （`perMachine: false`）で利用者が書ける場所に置くと、書き換えて通信先を足せてしまう。
  - 差し替え（`ELECXSTOCK_NEWS_FEEDS`）はスタブのとき（`ELECXSTOCK_PROVIDER=stub`）だけ効く（`ELECXSTOCK_NOW` と同じ扱い）。
- **読むのは Core だけ**。main は JSON を読まず、Core の準備ができたときに全フィードの `linkHosts` を受け取る（§9）。
- **検証**: `schemaVersion` と zod（`src/shared/news/schema.ts`）。知らない `schemaVersion` は全体を使わない（ニュースは「使えません」）。
  合わない行は捨てて残りを使い、ログに残す。L2 のテストは厳格で、1 行も捨てないことを確かめる。
- 版を上げずにネットワークから取り直すことはしない（通信先を増やさない）。news-feeds.md の表は JSON から作る（`npm run gen:news-feeds-doc`）。

```jsonc
{
  "schemaVersion": 1,
  "feeds": [
    {
      "id": "en.bbgmkt",
      "lang": "en",
      "name": { "ja": "Bloomberg Markets", "en": "Bloomberg Markets" },
      "short": "BBG",
      "url": "https://www.bloomberg.com/feeds/markets/news.rss",
      "group": "market",
      "linkHosts": ["www.bloomberg.com"],
      "defaultOnFor": ["ja", "en"],
      "listFor": ["ja", "en"],
      "summary": false,
      "copyright": "© Bloomberg L.P.",
      "keepDays": 7,
      "staleDays": 3,
      "terms": { "url": "https://www.bloomberg.com/notices/tos/", "checked": "2026-11-17" }
    }
  ]
}
```

| 項目                         | 意味                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------- |
| `id`                         | `ja.jpx` など。設定・既読・キャッシュのキー。変えない                                  |
| `lang`                       | フィードの言語（`ja` / `en`）                                                          |
| `name`・`short`              | 出所の名前（必ず出す）と印（全角 3 字・半角 5 字まで）                                 |
| `url`                        | https だけ                                                                             |
| `group`                      | `market`（市況・経済）／ `reading`（読み物）／ `official`（公的機関）                  |
| `linkHosts`                  | 記事のリンクのホスト（実際のフィードから集める。契約テストで確かめる）                 |
| `defaultOnFor`               | 表示言語がこれのとき既定でオン。**`terms.checked` が無いと空でなければならない**（L2） |
| `listFor`                    | 設定の、どの言語の一覧に出すか（省略は `[lang]`）。Bloomberg は日本語の一覧にも出す    |
| `summary`                    | 要約を出してよいか（出さないものはキャッシュにも持たない）                             |
| `copyright`                  | 詳細の行とコピーに添える権利の表記（あれば）                                           |
| `keepDays`                   | キャッシュに持つ日数（既定 30。Bloomberg は 7）                                        |
| `paywall`・`undated`・`zone` | 有料の印・日付なし（初めて見た時刻で並べる）・時刻帯の無い日付の既定                   |
| `staleDays`                  | 契約テストで「止まった」と見なす日数                                                   |
| `terms`                      | 規約の URL と、確かめた日（null は未確認）                                             |

### 2.1 Bloomberg の規約（2026-11-17 に確認）

読んだもの: [Bloomberg Terms of Service](https://www.bloomberg.com/notices/tos/)（www.bloomberg.com と Bloomberg L.P. の運営するサイト・アプリに
効く。施行日の記載なし・ニューヨーク州法）と、フィード（`feeds.bloomberg.com/markets/news.rss`。実装時に `www.bloomberg.com/feeds/markets/news.rss` へ 301 で移っていた。§14）の中身。**RSS だけに向けた利用条件は
見つからなかった**（規約にも、検索でも）。フィードの `<copyright>` は「Copyright 2026 BLOOMBERG L.P. ALL RIGHTS RESERVED」。
法律の専門家の判断ではない。

| 規約の箇所 | 内容（要旨）                                                                 | このアプリでの扱い                                                                                                      |
| ---------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| A.3        | 使えるのは「自分の非商用の利用」だけ                                         | 読むのは利用者本人。elecxstock は無償。業務の PC で読むと「非商用」から外れうることを README に書く                     |
| A.3        | 書面の許可なく、複製・配布・**改変・二次的著作物の作成**などをしてはならない | **訳さない・作り変えない**（翻訳の機能を持たない）。見出しは配信元の文のまま出す                                        |
| A.3        | 書面の許可なく scraper・robot などで取得・複製・監視してはならない           | RSS は読者アプリが読む前提で公開されている。間隔は 5 分以上・条件付きの要求で、読者アプリとしての通常の使い方にとどめる |
| A.3        | 情報でデータベースを作ってはならない                                         | キャッシュは最新の分だけ（1 フィード 30 件・7 日）。要約は持たない                                                      |
| C.3        | ページのキャッシュ・保存・ミラー・転載・再配布は許可が要る                   | 要約を出さず、記事はブラウザで Bloomberg のページを開く                                                                 |
| C.2        | 公開ページへのリンクは許される                                               | 記事はリンクで開く                                                                                                      |

**決めたこと**: 見出しとリンクだけを出す（`summary: false`）・詳細の行に「© Bloomberg L.P.」・キャッシュは 7 日・**日本語の表示でも既定でオン**
（`defaultOnFor: ["ja", "en"]`）。翻訳はしない（§6）。コピー（§7.4）は利用者が自分で使うためのもので、アプリが配布するものではない。

| ---------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

- Fed（米国の連邦機関の著作物は米国では著作権の保護を受けない）・ECB・金融庁などは既定でオフのまま。既定でオンにするときに確かめる。

## 3. 設定・ポリシー・保存

### 3.1 ニュースの設定（`data/news/settings.json`）

アプリの `Settings`（settings.json）には足さない。読み書きは `news.settings.get` / `news.settings.set`（zod・既定値との浅いマージ・平たい項目）。

| 項目               | 型                        | 既定   | 意味                                                                                       |
| ------------------ | ------------------------- | ------ | ------------------------------------------------------------------------------------------ |
| `enabled`          | `boolean \| null`         | `null` | `null` は未回答（取らない）                                                                |
| `interval`         | number（分）              | 10     | 1〜4 は 5 に丸める。**0（空欄）は、起動してペインが初めて見えたときに 1 回**。上限 1440    |
| `feeds`            | `Record<string, boolean>` | `{}`   | 利用者が変えたフィードだけ。無いものは `defaultOnFor` に従う                               |
| `acceptedDefaults` | `string[]`                | `[]`   | 答えたときに既定でオンだったフィード。後の版で既定オンが増えても黙ってオンにしない（§8.1） |

- 書き出し（利用者のデータ）には入れない。PC を移すと選択は消える（README に書く）。
- 状態（既読・「ここまで見た」・案内を出したか）は設定に入れず、キャッシュに置く。プレビューの出し入れはペインの状態（`pane.state`）。
- 間隔の読み取りは `src/shared/news/settings.ts` の `intervalFromInput()`。

### 3.2 管理者のポリシー

- **main が読んで Core に渡す**: レジストリの `HKLM\Software\Policies\elecxstock` の `News`=0 と、環境変数 `ELECXSTOCK_NEWS=off`。
  インストール先のファイルは使わない（利用者が書けるため）。
- 停止のとき Core はニュースの fetch を作らない。設定の画面は「管理者が切っています」と出して触れなくする。

### 3.3 保存（`data/news/`）

| ファイル        | 中身                                                                                                 |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| `settings.json` | §3.1                                                                                                 |
| `cache.json`    | 最後に取った見出し（フィードの `keepDays` まで）・ETag・既読（30 日・5000 件）・`seenAt`・案内の済み |

全データの削除（設定のデータ）の対象。ニュースを切るとき「取った見出しを消す」も選べる。SQLite には触れない（elecxstock-cli に影響しない）。

## 4. 取得（Core の `src/core/news/`）

elecdex の `FeedService` の作りを借りる（時計・タイマー・通信・保存を注入して、予定を単体テストできるようにする）。

### 4.1 いつ取るか

- `enabled === true`・ポリシーの停止なし・初回の取り込みが終わっている・二重起動の読み取り専用でない。
- かつ **見えている窓に `news` のペインがある** 間。renderer は `news.watch({ on })` を送る。
  main は窓を隠した（トレイ・最小化）ときに、その窓の分を外すよう Core に知らせる（新しいメッセージ `news.windowHidden`）。ポートが閉じても外す。
- 見えるようになったとき、最後の巡回から間隔が過ぎていれば 1 回取る。スリープからの復帰では各フィードを 0〜30 秒ずらす。

### 4.2 間隔

- **利用者の値を正とする**。全フィードを 1 回の巡回にまとめ、`interval` ごとに回す（ペインの「次 HH:MM」が正しくなる）。
- `<ttl>`・Cache-Control で間隔を延ばさない（条件付きの要求なので変わらなければ 304）。設定のフィードの行に参考として出す。
- 守るのは 429・503 と Retry-After だけ（そのフィードを、その時刻まで飛ばす。上限 24 時間）。
- 失敗は前の見出しを出したまま、5・15・30・60 分で取り直す。オフラインの間は失敗に数えない。
- 手動はペインの `R`。同じフィードを 60 秒以内には取り直さない。

### 4.3 通信

- **fetch は `worker.ts` が作って渡す**。`worker.ts` は差し替える前の fetch から、ニュースの fetch（`newsFetch`）を作って `NewsService` に注入する。
  `src/core/news/` は `globalThis.fetch` に触れない。
  - `newsFetch`: `src/core/netGuard.ts` の `guardFetch`（リダイレクトの行き先も確かめる。2026-11-17 に直した）を使う。オンのフィードは
    設定で変わるので、`guardFetch` の許可を **述語 `(url: URL) => boolean`** でも渡せるように広げ（今の `RegExp[]` も残す）、ニュースは
    「https・オンのフィードのホストの完全一致」を毎回の要求で判断する。Cookie・Referer は送らない。
  - 既存の `globalThis.fetch`（Yahoo・JPX・GitHub）にはニュースのホストを足さない。**`www.jpx.co.jp` は両方に入る**（上場銘柄の一覧とニュース）。
    L3 の「ニュースの fetch で Yahoo へ、既存の fetch でフィードのホストへ、どちらも出られない」は、重ならないホスト（Yahoo と日銀など）で確かめる。
- User-Agent は `elecxstock/<版>`（連絡先は入れない）。条件付きの要求。1 本 2 MB まで。同時に 2 本。データの取得ジョブとは別の列。

### 4.4 読み取りと整え方

- RSS 2.0・RDF・Atom を同じ関数で読む（elecdex の `parse.ts`）。エンティティは展開せず自前で解く。依存に `fast-xml-parser`（MIT）を足し、
  `scripts/gen-notices.mjs` の `bundled` にも足す。
- 文字コード: Content-Type の charset → XML 宣言 → UTF-8。Shift_JIS が utilityProcess の ICU で解けるかを L3 で確かめる。
- リンク: http は https に上げ、hostname がそのフィードの `linkHosts` に完全一致するものだけを残す（ほかは「リンクなし」）。`utm_*` を外す。
- 日付: 時刻帯なしは `zone`、`JST` などの略号は置き換えの表、未来は今に丸める、日付だけは時刻を出さない。`undated` は初めて見た時刻と「≈」。
- `summary: false` のフィードは要約を読み捨てる（キャッシュにも持たない）。
- 重複は正規化したリンクで 1 件に。「全て」に 1 フィードから出すのは新しい順に 30 件まで。時刻は日本時間（FR-T1）。

### 4.5 既読

開いた見出しは既読（文字を薄く）。未読の数・「全部既読」は持たない。代わりに **「ここまで見た」の線**（ペインが最後に見えていた時点）。
初回に取った分はすべて線より下。フリーの窓も Core の 1 つの記録を使い、`news.changed` で全窓にそろえる。

## 5. API と知らせ（`src/shared/news/api.ts`）

`NEWS_PARAMS`・`NewsResults`・`NewsEvents` をまとめ、`src/shared/api.ts` は取り込むだけにする。

| メソッド                      | 引数                 | 返す・動き                                         |
| ----------------------------- | -------------------- | -------------------------------------------------- |
| `news.list`                   | なし                 | `{ items, feeds: NewsFeedStatus[], round, state }` |
| `news.watch`                  | `{ on }`             | 窓ごと。和で判断                                   |
| `news.refresh`                | なし                 | 今すぐ確かめる                                     |
| `news.markRead` / `news.seen` | `{ key }` / `{ at }` |                                                    |
| `news.settings.get` / `.set`  | なし / 部分の設定    | §3.1                                               |
| `news.clearCache`             | なし                 |                                                    |

- `NewsItem` は `{ key, feed, at, approxAt, title, summary?, link? }`。
- `state`: `'unanswered' | 'off' | 'policy-off' | 'unavailable' | 'on'`（`unavailable` は登録表を読めない）。
- 知らせ: `news.updated`（見出しが届いた）と `news.changed`（設定・既読・「ここまで見た」）を全窓へ。
- **窓の制限**（`dispatch.ts`）: ニュースのペインはフリーの窓（2〜4 枚目）に置かない（§7.1）。念のため、フリーの窓からの `news.*` は
  `news.list` を除いて断る（`blockedInFree` と同じ考え方）。

## 6. 翻訳は持たない

v3〜v4 では、elecdex の PLaMo 3 Translate で英語の見出しを日本語に訳す案を検討したが、**見送った**（2026-11-17）。

- Bloomberg の規約（§2.1。A.3）は、書面の許可なく改変・二次的著作物を作ることを禁じている。アプリが訳文を作る作りは、自動でも
  ボタンでも、この条文に触れうる。
- 代わりに、ペインの見出し・要約・出所・URL を**コピーできる**ようにし（§7.4）、利用者が自分の意志で別のアプリ（翻訳のサービスなど）で
  訳せるようにする。elecxstock は訳文を作らない・持たない。
- 翻訳の部品（elecdex の検出・llama-server・別のプロセス・ループバック）は作らない。設定にも翻訳の項目は置かない。

## 7. ペイン（`news`）

### 7.1 置き場所

マーケットのタブの **左の列の下、ランキングの下**。右の列は今のまま:

```
R([30, 70],
  C([30, 36, 34], P('board', 1), P('ranking', 1), P('news', 0)),   // ニュースは銘柄を持たないのでリンク色なし（0）
  C([75, 25], R([60, 40], P('heatmap'), C([70, 30], P('chart', { tf: 'D' }), P('breadth'))), P('market')))
```

- 1680×1000 で約 500×300px（見出しとタブを 1 段にまとめて、1 行の行で 9〜10 件）。1366px 幅では約 410px で 2 行の行（5〜6 件）。
  比率は実装のあとにスクリーンショットで実測して決め直す。
- ランキングは 60% → 36%（20 行 → 約 12 行）、マーケット一覧は 40% → 30%。分け目は利用者が動かせる（FR-L4）。
- 既存の利用者のマーケットのタブは自動では変えない。Ctrl+Shift+N で入れられる。初めて版を上げた起動で、一度だけ案内を出す。
  （FR-L9 は大きさしか戻さないので使えない。）
- マイレイアウト（1 枚目）には置ける。**フリーの窓（2〜4 枚目）には置かない**（`FREE_WIDGETS` は「チャートを並べるものだけ・一覧を置かない」
  方針。design-multimonitor.md。未回答のときの「取る」や設定もフリーの窓からは書けないため）。

### 7.2 見た目

```
ニュース  全て 48  市況 21  読み物 12  公的機関 9        ⚠ 2  11:20 確認 · 次 11:30  ⌕
 今日 · 11/17（火）
 11:18  JPX   売買単位の変更に関するお知らせ
 11:15  BBG   Asian stocks edge lower as traders weigh rate outlook      英語
 ─────────────── ここまで見た ───────────────
 10:52  日銀  金融政策決定会合における主な意見
Bloomberg Markets · www.bloomberg.com · © Bloomberg L.P.          Ctrl+C コピー
```

- **見出しの段にタブを入れる**（1 段減らして行を増やす）。0 件のタブは出さない。
- **行**: 時刻（等幅・`--text-3`）・出所（固定幅の文字・`--text-2`）・見出し・印（「英語」「有料」「リンクなし」。枠だけ・`--text-3`）。
  表示言語と違う言語の見出しは `lang` 属性を付ける（読み上げ・フォント）。未読と既読は文字の濃さだけ。行の罫線は引かない。日付の見出しは sticky。
- **狭いとき**（480px 未満。コンテナクエリ）: 2 行の行。印は消さない。見出しの右は ⚠ と時刻だけ。
- **詳細の行**（一覧の下に常に 1 行）: 選んだ見出しの出所・開く先のホスト・権利の表記（`copyright`）・`Ctrl+C コピー`。
- **プレビュー**（要約）: 本体が 300px 以上あるときだけ詳細の行の下に出す。幅 900px 以上なら右に出す。`P` で出し入れ（ペインの状態）。
  要約を出さないフィードは「要約は出しません（配信元の条件）」、要約を許していても空の見出し（日銀など。RSS の description が空）は「要約はありません」。プレビューと詳細の行の文字はマウスで選んでコピーできる（`user-select: text`）。
- **見出しの右**: 「⚠ 2」（あれば）・「11:20 確認 · 次 11:30」。巡回中は「確認中 3/9」。間隔 0 なら「起動時に確認」。
- **新しい見出し**: 選んでいる行は中身で持ち、動かさない（`SelectionFollow`）。上に「↑ 新しい見出し 3 件（Home）」の帯。
- a11y: `role="listbox"`・`option`・`aria-selected`。

### 7.4 コピー

利用者が見出しを別のアプリ（翻訳・メモ・チャットなど）で使えるように、文字でコピーする。**コピーするのは利用者の操作のときだけ**で、
アプリが外へ送ることはない。

- **Ctrl+C（選んだ見出し）**: 次の形の文字（プレーンテキスト）。要約は出してよいフィードだけ。権利の表記があれば添える。

  ```
  Asian stocks edge lower as traders weigh rate outlook
  Bloomberg Markets · 2026-11-17 11:15 JST
  https://www.bloomberg.com/news/articles/…
  © Bloomberg L.P.
  ```

- **Ctrl+Alt+C（表示中の見出し）**: 今のタブ・絞り込みで見えている見出しを、1 行 1 件（`11/17 11:15  BBG  見出し`）で、上から最大 100 件。
  最後に出所と権利の表記をまとめて添える。リンクは付けない（長くなるため。1 件ずつは Ctrl+C で）。
- **時刻の書き方**（両方で同じ。日本時間）: 1 件は `2026-11-17 11:15 JST`、まとめては `11/17 11:15`。日付の無い見出し（`undated`）は
  初めて見た時刻に `≈` を付ける（`≈11/17 11:15`）。日付だけの見出しは時刻を書かない（`11/17`）。
- **マウス**: プレビューと詳細の行の文字は選んでコピーできる（右クリックのメニューは作らない。キーで全部できる）。
  **文字の選択がニュースのペインの中にあって空でないときの Ctrl+C は、選んだ文字をそのままコピーする**（ペインのコピーにしない。アプリの
  メニューは無いが、Chromium の既定のコピーが効く）。ほかのペインに残っている選択では、ペインのコピーをする。絞り込みの入力欄にいるときの
  Ctrl+C は、入力欄のコピーのまま（入力欄ではペインのキーを読まない）。
- **キーの割り当ての上書き**（FR-KB6）: Ctrl+C・Ctrl+Alt+C はペインのキーなので、全体のアクションに割り当てられると先に取られる。
  キーの設定で、この 2 つは全体のアクションに割り当てられないキーにする（`keymap` の検証で弾く）。
- 書き込みは main の clipboard（`window.elecxstock.copyText(text)`。preload と `src/shared/bridge.ts` の型に足す）。main の `app:copyText` は
  ほかのハンドラと同じく `fromApp` で送り手を確かめ、文字列だけ・100 KB まで・改行とタブ以外の制御文字を除く。renderer の
  `navigator.clipboard` には頼らない（カスタムのプロトコルで動かないことがあるため）。
- コピーしたら「コピーしました（1 件）」「コピーしました（23 件）」をトーストで出す。100 件で切ったときは「コピーしました（100 件まで）」。
- 文字の組み立ては `src/shared/news/copy.ts` の純粋な関数（`copyOne`・`copyList`）。L1 でテストする。
