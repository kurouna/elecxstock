# アラート（設計）

要求は [requirements.md](requirements.md) §6.14（FR-AL1〜AL10、NFR-AL1〜AL2）。画面のモックは [mock/alerts.html](mock/alerts.html)。
[design-p3.md](design-p3.md) §6 の案（`kind: 'above' | 'below' | …` の固定の種類）を置き換える。

## 1. 方針

- **条件はスクリーナーと同じ形**（`Condition`）。判定もスクリーナーの判定を使う（`screener.ts` に、条件の検証・版の移行（`conditionValid`・`migrateConditions`）を通したうえで 1 銘柄ずつ判定する関数を公開する。いまの `test` は非公開）。アラートのための指標や比べ方を別に作らない。
- **使える条件を絞る**（zod で検証）: 数値の市場の指標（`metrics` の列）と保有の損益率（`holding.pnlPct`）だけ。比べ方は `>=` `<=` と相対条件（`ref`）。`or`・`includeMissing`・属性（市場・業種）・利用者の印（★・ウォッチリスト）は使えない。
  - 比べ方に `<` は無い。「終値が 75 日線を下回る」は「終値 ≤ 75 日移動平均 +0%」と書く。エッジ（§3.1）と組み合わせると「下回った瞬間」に鳴るので、「抜けた」専用の型は要らない。
  - 指標の登録表に価格は終値（`price.close`）しかない。始値・高値・安値の条件は持たない。
- **判定は Core**。取得のジョブが終わったときに 1 回（§3.2）。
- **アラートは Core が持つ利用者のデータ**。ウォッチリストのように renderer が持って配列ごと保存する形にはしない（判定する Core が正本を持ち、どのウィンドウからも同じ口で変える。`watchlists.toggleItem` と同じ考え方）。
- **外へは送らない**。知らせはアプリの中と Windows の通知だけ。

## 2. データ

```ts
/** アラートの定義（alerts.json。利用者のデータ。世代のバックアップ・書き出し・取り込み・元に戻すの対象） */
interface Alert {
  id: string
  target: { kind: 'symbol'; id: InstrumentId } | { kind: 'screen'; screenId: string }
  /** 銘柄のアラートの条件（1〜3 個、「かつ」）。スクリーンのアラートでは空 */
  conditions: Condition[]
  /** 価格のしきい値の基準日（作った日・直した日）。これより後の分割・併合で換算する（§3.3） */
  basis: JstDate
  repeat: boolean // 成り立ち直すたびに鳴る / 1 回だけ（鳴ったら enabled = false）
  enabled: boolean
  note?: string
  created: string // ISO
}

/** 判定の状態（alertState.json。世代なし・書き出しの対象外。Core だけが書く） */
interface AlertState {
  met: boolean | null // 前の判定で成り立っていたか。null はまだ基準が無い
  asOf?: JstDate // 前に判定した基準日（同じ基準日では判定しない）
  members?: InstrumentId[] // スクリーンのアラート: 前の判定の結果
  lastFired?: string
  invalid?: 'missing' | 'stale' | 'suspect' | 'delisted' | 'noScreen' | 'noHoldings'
}

/** 鳴った記録（alertHistory.json。世代なし・書き出しの対象外。最大 500 件） */
interface AlertFire {
  id: string
  alertId: string
  at: string
  instrument: InstrumentId
  /** 判定に使った値（指標 ID → 値）、換算したしきい値、基準日（NFR-AL2） */
  values: Record<string, number | null>
  threshold?: number
  splitAdjusted?: boolean
  asOf: JstDate
  provisional: boolean // 大引け後の気配から作った仮の足で判定した
  read: boolean
}
```

- **定義と状態を分ける**: 状態を `alerts.json` に入れると判定のたびに書くことになり、`UserStore.save` が毎回世代のバックアップを作って 10 世代が状態の更新で埋まる。状態と履歴は世代なしの別ファイル（`resetMarketData` で消えない場所）に置く。
- **読み取り専用**（`UserStore.readOnly`）のときは `save` が投げる。判定は try/catch で包み、ジョブを失敗させない（状態はメモリにだけ持つ）。
- 書き出し・取り込み・元に戻す（`exportAll`・`importAll`・`user.undoImport`）の対象の列挙に `alerts` を足す。取り込んだら状態を捨て、存在しないスクリーンのアラートは落とす。
- 変更の知らせ: `ChangeKind` と `Events['user.changed']` に `alerts` を足す（`src/core/changes.ts`）。
- **取得の対象**: アラートの銘柄を `trackedCodes()` と優先の対象（`listed()`）に足す。プライム・J-REIT 以外の銘柄に付けたアラートも更新される。上場廃止の銘柄は `invalid: 'delisted'`。

## 3. 判定（Core）

### 3.1 鳴り方（FR-AL4）

| 前回 `met`                                                           | 今回         | 動き                                                           |
| -------------------------------------------------------------------- | ------------ | -------------------------------------------------------------- |
| `null`（作った・直した・再開した直後、保有を変えた直後の保有の条件） | true         | 鳴らさない。一覧に「成立中」                                   |
| `null`                                                               | false        | 何もしない                                                     |
| false                                                                | true         | **鳴る**。1 回だけのアラートは `enabled = false`               |
| true                                                                 | true         | 鳴らさない（成り立ち続けている）                               |
| true                                                                 | false        | 何もしない（次に成り立ったらまた鳴る）                         |
| どれでも                                                             | 判定できない | `met` は変えず、`invalid` に理由を書く。一覧に「判定できない」 |

- 休場日は値が変わらないのでエッジが出ない（何もしない）。
- 閉じていた間に成り立ってまた外れた分は検知しない（最新の値だけを見る。FR-AL3）。

### 3.2 判定のとき（FR-AL3）

- **ジョブが終わったとき**（`JobRunner.loop()` で状態を `done` にした所）に、`JobsHost` のコールバックで 1 回判定する。指標の再計算の項目（`X`）では判定しない（日々の更新は `[Q…, X, M…]` で、ウォッチリスト・保有以外の銘柄の取り直しは `X` のあとに積まれる。取り直しのジョブには `X` が無い）。
- `recomputeAll` を直接呼ぶ所（起動時の `metricsStale`・`jobs.applyRetention`）も、終わりに同じ判定の口を通す。
- **判定しない銘柄**（`invalid`）:
  - 初回・全データの取り直しのジョブが残っている間はすべて（値がそろっていない）。
  - 分割の疑い（`gapSuspect`）・値の異常（`anomaly`）のある銘柄（分割の日は、気配から作った新しい基準の仮の足と、古い基準の日足が混ざり、「終値 ≤」が誤って鳴るため）。
  - 基準日が直近の営業日より古い銘柄（取得に失敗している）。
- **基準日が進んだ銘柄だけ判定し、同じ基準日では 1 回まで**。気配から来る PER・PBR・時価総額は場中の F5 でも変わるが、基準日が同じなら判定し直さない。
- **仮の足**: 仮の足は、気配の時刻が大引け（15:30）以降のときだけできる（FR-D8）。大引け後の更新で仮の足の終値で鳴ったときは `provisional` を付け、履歴と通知に「仮の値」と出す。翌日に仮の足が確定値で置き換わっても、鳴った記録は残す。
- **保有を変えたとき**（`portfolio.save` など）は鳴らさず、保有の条件の `met` を今の値で取り直す（自分の入力で鳴らないように）。
- **大量に鳴るとき**: 1 回の判定でトースト 1 つ・通知 1 つにまとめる（「アラートが 12 件鳴りました」）。履歴には全部残す。スクリーンのアラートは 1 回の判定で 20 件まで、残りは「ほか N 件」。

### 3.3 分割・併合としきい値（FR-AL1）

- 価格は分割調整済みで保存するので、分割の前に決めた価格のしきい値は、そのままでは狂う（1:5 の分割で、15,000 円のしきい値は 3,000 円に相当する）。
- 金額の指標（`format: 'money'`）で相対条件の無い条件は、`basis`（作った日・直した日）より後の分割・併合の比率で割って比べる（`holdings.ts` の `normalize` と同じ考え方）。一覧と履歴に「分割で換算」と出し、元のしきい値と換算後の値を両方見せる。
- 利回り・PER・騰落率などの比率の指標と、相対条件は換算しない（分割で変わらない）。

### 3.4 速さ（NFR-AL1）

- 判定に使う指標はジョブの終わりに一度読み込む（`emitData` が指標のキャッシュを消すため、メモリにあるとは限らない）。読み込みを除けば、500 件の銘柄のアラートは単純な比較で数 ms。
- スクリーンのアラートはスクリーンの数だけ `runScreen` を回す（1 回 10ms 程度、2,000 銘柄）。スクリーンのアラートは 20 件までにする。
- 単体テストで 500 件を 100ms 以内（読み込みを除く）に判定できることを確かめる。

## 4. API（`src/shared/api.ts`）

| メソッド            | 入力                      | 返すもの                                                                   |
| ------------------- | ------------------------- | -------------------------------------------------------------------------- |
| `alerts.list`       | なし                      | アラートと状態（現在の値・条件までの距離・換算後のしきい値を添えて）       |
| `alerts.save`       | `Alert`（新規は id なし） | 保存したアラート。保存したら基準を取り直す（`met` を今の値で。鳴らさない） |
| `alerts.remove`     | `id`                      | 消したアラートと状態（取り消し用）                                         |
| `alerts.restore`    | 消したアラートと状態      | id と状態を保ったまま戻す（Ctrl+Z の取り消し）                             |
| `alerts.setEnabled` | `id`, `enabled`           | アラート（再開したら基準を取り直す）                                       |
| `alerts.history`    | `limit`                   | `AlertFire[]`                                                              |
| `alerts.markRead`   | `ids` か `all`            | 未読の数                                                                   |
| `alerts.unread`     | なし                      | 未読の数（起動時にベルが読む）                                             |

- イベント `alerts.fired`（鳴った `AlertFire[]` と未読の数）。
- **条件までの距離**: 成り立っていない条件のうち、いちばん遠いもの。価格・相対条件は「あと何 %」、比率の指標は差（「あと 0.4pt」）。成り立っていれば「成立中」。

## 5. 知らせ方（FR-AL5）

- **トースト**（renderer、1 枚目だけ）: 1 件なら「アラート: 7203 トヨタ自動車 終値 ≤ 17,500（17,480）」。押すとその銘柄を銘柄ジャンプと同じ規則で開く。複数なら「アラートが 3 件鳴りました」で、押すとアラートのポップアップ（履歴）を開く。
- **Windows の通知**: Core は文言を持たない（エラーと同じく、文言は renderer の i18n。FR-N5）。1 枚目の renderer が文言を作り、preload に足す `notify(title, body)` で main に頼む。main は `Notification` を 1 つ出し、押されたら 1 枚目を前面に出して履歴を開く。
  - 通知の本文は銘柄と条件だけ（画面ロック中に見られるため。保有の条件のときは「保有の条件が成り立ちました」とだけ）。
  - 署名の無いアプリで通知が出るかは、実装の前に確かめる（`setAppUserModelId` は設定済み）。
- **ベルと未読の数**: 起動時の再開したジョブ（`jobs.resume()`）はウィンドウがつながる前に鳴りうるので、ベルの未読の数は起動時に `alerts.unread` で読む。

## 6. 画面

### 6.1 アラートのポップアップ（FR-AL8）

ペインは持たない。トップバーのベルか Ctrl+Alt+L で、画面の上寄りに重ねて開く（コマンドバー・スクリーンの一覧と同じ位置。上から 72px で、件数が変わっても見出しの位置が動かない。`app.overlay = { kind: 'alerts', tab }`。スクリーンの一覧（Ctrl+O）と同じオーバーレイ）。どのタブで開いてもレイアウトは変わらず、Esc で閉じれば元のまま。

```
┌ アラート  [アラート 8 | 履歴 2]  ☐ 成立中だけ                                 ✕ ┐
│ 状態         銘柄                   条件                        現在     条件まで │
│ ● 有効       7203 トヨタ自動車      終値 ≤ 17,500               18,600  −5.9%    │
│ ◎ 成立中     8951 日本ビルファンド  実績利回り ≥ 5.5%           5.66%   成立中   │
│ ● 有効       9434 ソフトバンク      終値 ≤ 75日移動平均 +0%     2,221   −4.1%    │
│ ● 有効       2914 日本たばこ産業    終値 ≤ 3,400 分割で換算     3,520   −3.4%    │
│ ! 判定できない 8306 三菱UFJ          終値 ≤ 18,000 … 分割の疑い   —       —        │
│ ○ 停止       3462 野村不動産MF      52週高値から ≤ −20%         −8.1%   11.9pt   │
│ ● 有効       [高配当銘柄]           新しく入った銘柄            14 件   —        │
│ Insert 作る · E 直す · Space 有効/停止 · Delete 消す · Enter 銘柄を開く ·       │
│ H 履歴 · Ctrl+Shift+F 成立中だけ · Esc 閉じる                                    │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- 開いたとき: 未読があれば履歴、無ければアラートの一覧。H で切り替え、R で履歴を既読に。未読は太字。
- キー: Insert 追加、E 編集、Space 有効と停止、Delete 削除、Enter 銘柄を開く、H アラートと履歴の切り替え、R 既読、Ctrl+Shift+F 成立中だけ、Esc 閉じる。↑ ↓ PageUp PageDown Home End で行を移る。
- **Enter（銘柄を開く）**: ポップアップを閉じ、フォーカスを開く前のペインに戻してから、銘柄ジャンプと同じ関数（`sendSymbol`）で送る。フォーカス中のペインのリンクグループ（リンク色が無ければリンク 1）に送り、今のタブにそのリンク色のチャート・銘柄情報が無ければ MTF のタブに移って日足に出す（FR-K1。「MTF で表示しました」）。リンク色の無いチャートにフォーカスがあれば、そのチャートだけを変える（FR-L11）。スクリーンのアラートは、スクリーナーでそのスクリーンを開く。
- 作る・直すダイアログ（§6.2）は、ポップアップの上に重ねる（閉じたらポップアップに戻る。いまのオーバーレイは 1 つなので、`confirm` などと同じく戻る先を覚えて開き直す）。
- **削除の取り消し**: 削除のトーストに「元に戻す」。10 秒以内なら Ctrl+Z でも戻す（いまの Ctrl+Z はサイズのリセットの取り消し専用（FR-L9）なので、§6.5 に「直前の削除の取り消し（10 秒以内）」として定義し直す）。`alerts.restore` で id と状態を保って戻す。
- フリーのウィンドウでは開かない（`blockedInFree`。アラートの変更は 1 枚目で）。

### 6.2 作る・直すダイアログ（FR-AL7）

```
┌ アラートを作る ──────────────────────────────────────────────┐
│ 対象   (●) 銘柄 [7203 トヨタ自動車      ]  ( ) スクリーン      │
│ 条件   [終値        ▾] [≤] [17,670      ]        いま 18,600   │
│  かつ  [＋ 条件を足す]                                        │
│ 鳴り方 (●) 成り立つたびに  ( ) 1 回だけ                       │
│ メモ   [押し目の買い増しを検討                    ]            │
│ いま: 成り立っていない（あと −5.0%）                           │
│                              [取り消し]  [作る]                │
│ Tab 項目を移る · 条件の行で F 指標 / O ≥ と ≤ / R 相対条件 /    │
│ ← → 値 · Space 選ぶ · Ctrl+Enter 作る · Esc 取り消し           │
└───────────────────────────────────────────────────────────────┘
```

- 条件の行の単キーは、スクリーナーの条件エディタと同じ（F 指標・O ≥ と ≤ の切り替え・R 相対条件・← → 値・Enter 値を入力）。**単キーは条件の行にフォーカスがあるときだけ効く**（メモ欄に文字を打てるように。FR-KB5）。
- 対象・鳴り方のラジオは Tab で移り、← → か Space で選ぶ。作るのは Ctrl+Enter（メモ欄の Enter と分ける）か「作る」ボタン。
- 開いたときの既定: フォーカス中の銘柄、指標は「終値」、比べ方は ≤、値は今の終値の 5% 下（下がったら知らせる、が一番多い使い方と見て）。
- 「いま」の行に、今の値で成り立つかを出す（作った直後に鳴らない理由が分かるように）。分割の換算が入るアラートを直すときは、元のしきい値と換算後の値を出す。

### 6.3 チャート（FR-AL9）

- 終値の条件（相対条件の無いもの）のアラートは、チャートに水平の点線（`createPriceLine`。色は `--warn`、価格の札にベルの印）。しきい値は分割で換算した値。停止中は薄く。

### 6.4 トップバー

- ベルのボタン（`Icon` に `bell` を足す）。未読があれば数の札。押すか Ctrl+Alt+L で、アラートのポップアップを開く（**未読があれば履歴、無ければアラートの一覧**）。もう一度押すと閉じる。ツールチップ「アラート (Ctrl+Alt+L)」。

## 8. マルチモニタ

- アラートは Core が持つので、フリーのウィンドウからも Ctrl+Alt+A で作れるようにする（AL2。`watchlists.toggleItem` と同じく、フリー N が書ける例外にする）。アラートのポップアップは 1 枚目だけ。変更は `user.changed`（`alerts`）で全部のウィンドウに届く。
- フリーのウィンドウのチャートにも、アラートの点線を出す。トーストと通知は 1 枚目だけ。

## 10. テスト

- **単体**（Core）:
  - §3.1 の表（作った直後・成り立ち続ける・外れてまた成り立つ・1 回だけ・停止と再開・判定できない）。
  - 判定のとき: ジョブの終わりに 1 回、同じ基準日では判定しない、初回の取り込み中・分割の疑い・古い基準日は判定しない。分割の日のジョブの順（仮の足と古い日足が混ざる日）で誤って鳴らない。
  - 分割の換算（基準日より後の分割だけ、比率の指標は換算しない）。
  - 保有を変えたら鳴らずに基準を取り直す。
  - 読み取り専用のとき、判定がジョブを失敗させない。
  - 取り込み（状態を捨てる・存在しないスクリーンのアラートを落とす）、上限。
  - 取得の対象外の銘柄（アラートを付けると取得される）・上場廃止。
  - 500 件を 100ms 以内（読み込みを除く）。
- **E2E**（スタブのデータ・キーボードだけ）: スタブのプロバイダを環境変数で動かして値を前後させる（テスト用の判定の入口を API に足さない）。Ctrl+Alt+A で作る → Ctrl+Alt+L のポップアップに出る（レイアウトは変わらない）→ F5 で更新して鳴る → ベルの未読の数 → ポップアップが履歴で開く → Enter で銘柄が開く（リンク色のチャートが無いタブでは MTF に移る）→ R で既読 → Space で停止 → Delete で消して Ctrl+Z で戻す。チャートに点線が出る。フリーのウィンドウではポップアップが開かない。
- 見た目の回帰: ダイアログの基準画像を足す。

| 重さ | 指摘                                                                                                  | 反映                                                                                                           |
| ---- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 重大 | 判定を指標の再計算（`X`）に置くと、取り直しが後ろに積まれ、分割の日には新旧の基準が混ざって誤って鳴る | ジョブの終わりに 1 回。分割の疑い・初回の取り込み中・古い基準日は判定しない（§3.2）                            |
| 重大 | 分割の前に決めた価格のしきい値が狂う                                                                  | 基準日を持ち、その後の分割で換算する（§3.3）                                                                   |
| 重大 | プライム・J-REIT 以外の銘柄のアラートは取得されず鳴らない                                             | アラートの銘柄を取得の対象に足す（§2）                                                                         |
| 重大 | 判定の状態を利用者のデータに入れると世代が埋まる。読み取り専用で例外になる                            | 定義と状態・履歴を分け、判定を try/catch で包む（§2）                                                          |

| 重要 | 判定の関数が非公開・検証を通らない、`<` が無い、始値などの指標が無い、距離が未定義                    | 公開する関数、使える条件の制限、表記の修正、距離の定義（§1・§4・§6.3）                                         |
| 重要 | スクリーンのアラートは上位 N 件が Core に無く、利用者の操作で大量に鳴る                               | 上位 N 件は対象外、基準の取り直し、外れたは既定で切る、20 件まで。AL3 で仕様を決め直す（FR-AL2）               |
| 重要 | 大量に鳴るとき・閉じていた間の扱いが仕様に無い                                                        | 1 回の判定でトースト 1 つ・通知 1 つ。閉じていた間の成立と解消は検知しない（FR-AL3・AL5）                      |
| 重要 | Core は文言を持たないので通知を出せない。起動時のベルの数                                             | renderer が文言を作り main に頼む。ベルは起動時に API で読む（§5）                                             |

## 14. その後に決めたこと

| 決めたこと                                                            | 理由                                                                                                                                                                                                                    |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| アラートの一覧は**ポップアップだけ**にし、ペインは持たない            | ペインを開く（`openPane`）と今のレイアウトに分割して差し込まれ、押すたびにレイアウトが変わる。アラートは時々見に行く一覧で、タブやペインを 1 つ使うほどの中身がない。常に表示したい要望が出たら、同じ部品でペインを足す |
| ポップアップの Enter は、銘柄ジャンプと同じ関数（`sendSymbol`）で送る | どのタブにいても必ずチャートで確かめられる（リンク色のチャートが無いタブでは MTF に移る。FR-K1）。動きがジャンプ・コマンドバーとそろう                                                                                  |

## 15. AL2・AL3 で決めたこと

| 決めたこと                                                                                                                                                                                                                                                                      | 理由                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **スクリーンのアラートは、新しく入った銘柄をアラートごとに 1 件の記録にまとめる**（`AlertFire` に `screenId`・`members`（20 件まで）・`more`。`instrument` は最初の銘柄）                                                                                                       | 銘柄ごとに記録すると、スクリーンの条件をゆるめた日などに履歴が埋まる。トースト・通知も 1 つにまとめる（FR-AL5）                            |
| **上位 N 件の設定は使わず、条件に合うすべての銘柄で判定する**                                                                                                                                                                                                                   | 上位 N 件は並べ替えの順で決まり、並べ替えはペインの状態にしかない（Core から見えない）。対象外にするより、全件で判定するほうが分かりやすい |
| **★・ウォッチリスト・保有の条件も使える**。Core が持つ利用者のデータで走らせる（`runSavedScreen`）                                                                                                                                                                              | 市場の指標に限ると、「保有の銘柄で利回りが 5% を超えた」のような使い方ができない。利用者の操作で鳴らないように、変えたら基準を取り直す     |
| **基準の取り直し**: スクリーンを保存し直したら条件の変わったスクリーンだけ（名前・並びの変更では取り直さない）、★・ウォッチリスト・保有を変えたらその条件を使うスクリーンだけ、利用者の銘柄を足す・外したらすべて（対象の銘柄が変わる）（`SCREEN_REBASE`。`call` の後ろで行う） | ★の切り替えは頻繁なので、関係の無いスクリーンまで走らせない（1 回 10ms 程度 × 20 件まで）                                                  |
| **基準日**: 指標の中でいちばん新しい基準日。同じ基準日では判定し直さない                                                                                                                                                                                                        | 銘柄のアラートと同じ考え方（場中の F5 で PER などが動いても鳴らない）                                                                      |
| **分割の疑い・値の異常の銘柄は、知らせず覚えもしない**（基準を取り直すときも）                                                                                                                                                                                                  | 分割の日は新旧の基準が混ざる（§3.2）。直ってから入っていれば知らせる                                                                       |
| **消したスクリーンのアラートは消さずに「スクリーンが無い」**                                                                                                                                                                                                                    | 取り込み・元に戻すでスクリーンが戻ることがある。利用者が自分で消す                                                                         |
| **スクリーンのアラートは「成立中」を持たない**。「現在」は結果の件数                                                                                                                                                                                                            | 結果に銘柄があるのはふつうのことで、成立中と出す意味が無い                                                                                 |
| **ダイアログの対象は ← → で銘柄とスクリーンを切り替える**。スクリーナーにフォーカスして Ctrl+Alt+A なら、開いているスクリーンが初めの対象。直すときは対象の種類を変えない                                                                                                       | 作る口を 1 つにする（キーを増やさない）                                                                                                    |
| **フリーのウィンドウからは新しく作ることだけできる**（`alerts.save` で id が空のとき。worker が確かめる）。直す・消す・止める・既読はポップアップのある 1 枚目だけ                                                                                                              | 利用者のデータの持ち主は 1 枚目（design-multimonitor.md）。★・◆と同じく、作るだけを例外にする                                              |
| **Windows の通知**: 1 枚目の renderer が文言を作り、preload の `notify` で main に頼む（`app:notify`。1 枚目からだけ受け付ける）。押されたら 1 枚目を前に出して履歴を開く（`alerts:open`）。設定「アラートを Windows の通知でも知らせる」（既定はオン）                         | Core は文言を持たない（FR-N5）。通知は画面ロック中にも見えるので、金額を出さない                                                           |
| **チャートの点線**: アラートの一覧（`app.alerts`）を全部の窓で持ち、ChartView が `createPriceLine` で引く。比較の表示（% 目盛り）では引かない                                                                                                                                   | ポップアップと同じ一覧を使う（読み直しは `alertsRev` が変わったとき・ジョブが終わったとき）                                                |

レビュー（AL1〜AL3 の実装）で直したこと: ポップアップを開いたままでも Ctrl+Z で削除を戻す、消して作り直したあとの取り消しでも上限を守る、
通知の参照を持って押されたことを受け取る、読み取り専用のときは判定の状態・履歴も書かない、ダイアログの既定の値は指標が届いたときに一度だけ入れる、
保有の集計を `heldFrom`（`src/shared/alerts.ts`）にまとめる。
