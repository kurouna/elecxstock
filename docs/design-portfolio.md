# ポートフォリオのダッシュボード（設計案）

保有銘柄をひと目で把握するための、ダッシュボード型のペイン「ポートフォリオ」（`folio`）と、それを置く 9 つ目のタブ、資産の推移を毎日記録する仕組みの設計。**次の版の目玉**にする。

- モック: [mock/portfolio.html](mock/portfolio.html)（値はすべて架空）。状態ごとのスクリーンショットは [mock/portfolio-shots/](mock/portfolio-shots/)
- 状態: **実装済み**（FR-PF1〜PF8。requirements.md §6.15）。実装で決めたことは 11 章
- 関連: 保有の一覧（`portfolio` ペイン。FR-H*）・保有の JSON（[holdings-format.md](holdings-format.md)）・アラートの記録（[design-alerts.md](design-alerts.md)）・配当カレンダー（`divcal`）

## 1. ねらい

今の「保有」ペインは**表**（口座ごとの小計・行ごとの損益）で、数字を確かめるのには向く。一方で、次の問いにはすぐ答えられない。

| 問い                                               | ダッシュボードの答え                                             |
| -------------------------------------------------- | ---------------------------------------------------------------- |
| 全体でいくら・今日どれだけ動いたか（市場と比べて） | ヒーロー（評価額・今日・日経と TOPIX の今日）                    |
| 資産はどう増えてきたか・入れたお金を除くとどうか   | 資産推移（評価額と取得額の間を含み損益の色で塗る）と期間の内訳   |
| 偏っていないか（業種・口座・銘柄）                 | 配分（2 段のツリーマップ・集中度）                               |
| 何が効いたか（今日・今月・今年・取得から）         | 寄与（全銘柄。値動きと配当を分けて積む）                         |
| 配当はいつ・いくら入るか。増減要因（前年比）       | 配当の見込み（12 か月と 前年同月）                               |
| 増えた配当は増配か買い増しか。どの銘柄・業種か     | **配当の分析**（年間・1 年の増減の内訳・分類ごと・銘柄ごとの表） |
| 近く何があるか                                     | 30 日の予定（権利付き最終日と配当見込み額・決算・アラート）      |

使う人は中長期の投資家を想定する。日々の値動きより、月・年の単位の成果と、配当の積み上がりを厚く見せる。

**まずグラフで見せる**。どのカードも、図を先に置き、数字はその図の読み方を助ける脇役にする（評価額と年間の配当の大きな数字だけは例外。一つの値は図にしない）。

| 情報                                               | 図                                                         |
| -------------------------------------------------- | ---------------------------------------------------------- |
| 資産の推移                                         | 評価額の線・取得額の階段・含み損益の帯                     |
| 期間の内訳（期首 → 入出金 → 値動き → 配当 → 期末） | 小さなウォーターフォール                                   |
| 配分                                               | 2 段のツリーマップ                                         |
| 寄与                                               | 0 を中心に左右へ伸ばす棒（値動き＋配当の金）               |
| 月ごとの配当                                       | 棒と 1 年前の破線の枠                                      |
| 30 日の予定                                        | 30 日の時間軸に点（種類を色と形で）                        |
| 配当の内訳（業種など）                             | ドーナツ（凡例を兼ねる一覧つき）                           |
| 配当の見込みの推移                                 | 記録の日ごとの金の線（段が増配・買い増し・売却）           |
| 1 年の配当の増減                                   | ウォーターフォール                                         |
| 分類・銘柄ごとの配当                               | 表のセルの中の小さな棒（割合・増減）と 1 株配当の 5 年の棒 |

## 2. 他のアプリの調べ（要約）

調べたアプリ:

- 国内: マネーフォワード ME・カビュウ・楽天証券 iGrow・SBI 証券・配当管理アプリ
- 海外: Sharesight・Snowball Analytics・getquin・Kubera・Empower・Yahoo Finance・Koyfin・Simply Wall St

分かったこと:

- **どのアプリにもある**: 総額と損益のヒーロー、資産推移（取得額の線と重ねる）、配分（業種・口座・銘柄）、保有の表。
- **国内で重視されている**: 配当の月ごとの棒、取得額に対する利回り、NISA 枠の状況、業種の円グラフ、配当の目標（「月 ○ 万円」）。
- **海外で重視されている**: ベンチマークとの比較、寄与の分析、集中度の警告、TWR と MWR の区別、配当の成長（増配率・連続増配・前年比）。
- **配当に強いアプリ**（Snowball・カビュウ・配当管理アプリ）が出しているもの: 年間と月平均、前年比、1 株配当の推移、増配率、連続増配、配当性向、業種ごとの配当の割合、目標の進み。**増えた理由を増配と買い増しに分けて出すものは少ない**（このアプリは毎日の記録で数量の変化が分かるので出せる。差別化になる）。
- **流行り**:
  - 大きさの違うカードを並べる bento 型
  - 暗い面に細い線
  - 等幅の数字
  - 選んだものを他の図でも強調する（ブラッシング）
  - ウォーターフォールで増減の内訳を見せる
- **落とし穴**:
  - 5 つを超える円グラフ
  - 赤と緑だけで上下を表す
  - カードごとに色の意味が変わる
  - 説明の無いスコア
  - 損益率の定義を書かずに混ぜる
  - すりガラスで数字が読みにくくなる

## 4. ペインの構成

一つのペインの中に、大きさの違うカードを格子に並べる（bento）。並びは `grid-template-areas` でペインの幅ごとに決め、穴を作らない（コンテナクエリ）。

ペインは縦にスクロールする 2 段の作り。上の段（**概要**）はペインの高さに合わせ、開いてすぐ全体が見える。その下に **配当の分析** が続く。

```
L（≥ 1180px）
┌────────────┬──────────────────────────────────────────┐ ↑
│ ヒーロー    │ 資産推移（評価額・取得額・含み損益の帯）        │ │
│            │ 期間の内訳（期首・入出金・値動き・配当・期末）   │ │ 概要
├────────────┴──────┬──────────────┬────────────────────┤ │（ペインの高さ）
│ 配分（2 段のツリー） │ 寄与（全銘柄・  │ 配当の見込み          │ │
│                   │  縦スクロール）│（12 か月と 1 年前）     │ │
├───────────────────┴──────────────┴────────────────────┤ │
│ 30 日の予定（時間軸とカード）                                  │ ↓
├────────────────────────────────────────────────────────┤ PgDn
│ 配当の分析                                               │
├────────────────┬──────────────────────┬───────────────┤
│ 配当の内訳       │ 年間の配当             │ 1 年でどれだけ   │
│（ドーナツ）      │（見込みの推移・目標）    │ 増えたか（滝）   │
├────────────────┴──────────────────────┴───────────────┤
│ 分類ごとの配当（アコーディオンの表。縦スクロール）        │
└────────────────────────────────────────────────────────┘
M（760〜1180px）: ヒーロー | 資産推移 / 配分 | 寄与 / 配当 | 予定（縦の一覧）/ 内訳 | 年間 / 増減 / 表
S（< 760px）: 1 列。ヒーローに 30 日の推移線を足す。配当の分析はドーナツから。表は列を減らす
```

### 4.1 概要のカード

| カード               | 中身                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ヒーロー**         | 評価額（大きな数字。**「現金除く」**と添える）、今日の損益（円・%）と**日経・TOPIX の今日**（記録が無くても初日から比べられる）。休日に開いたときは「今日」ではなく「11/13（金）」と日付で出す。2 列の細い区切りで: 含み損益（円・%）、取得額、**トータル損益**（含み＋実現＋受取配当。CSV の累計）、**最高値比（記録内）**、**前回記録比**（毎日開くとは限らないので、前日比だけでは足りない）、PER（調和平均）・β。口座の帯（細い線と点だけ）、**NISA 簿価**（細い棒。6.3）                                                                                                                                                                                                                                                                                                                     |
| **資産推移**         | 評価額は中立の色の線、取得額は破線の階段。**その間の帯を含み損益の色で塗る**（取得額より上は `--up`、下は `--down`）。含み損益をそのまま絵にする、このペインの顔になる図。補完値（記録なし。埋めた値）は白抜きの点。期間は「記録」（既定。記録の初日から）・1M・3M・6M・1Y・全。見出しの主役は**含み損益**（帯の色と一致する）で、**評価損益の増減（入出金除く）**は中立の小さな値で添える。下に**期間の内訳**を小さなウォーターフォールで（期首 → 入出金 → 評価損益の増減 → 期末。足すと期末と一致する。入出金は損益ではないので中立の色。**受取配当は評価額（現金を含まない）に入らないので橋に入れず、右上に「受取配当（別枠・現金）」として添える**。値は万円・小数 1 桁にそろえる。両端は下を切り、波線で示す）。% にすると時間加重の概算（6.2）と、ベンチマーク（記録が 20 日貯まってから） |
| **資産構成**         | ツリーマップ。面積は評価額、色は含み損益率か前日比を**5 段の発散**で塗り、目盛りを添える。長く持つ保有は含み益が多く、濃い色だと一面が警告の色に見えるので、**混ぜる割合は 12〜55%**（ヒートマップのペインより控えめ。同じ関数に割合を引数で渡す）。分類の見出しは中立の帯（`--panel-2`）に小さな色見本・割合・損益率を書き、幅が足りなければ省略記号で切る。小さいタイルは銘柄コードだけ、もっと小さいタイルは何も書かない（選ぶと詳細）。分類は業種・口座・種別・銘柄。業種・口座・種別は**2 段**（分類の見出し → 銘柄）。口座で分けても色は損益のまま、口座は左の 3px の帯で示す。文字の色は背景から計算してコントラストの高いほう。上に集中度（最大保有比率・上位 5 銘柄・**実効銘柄数** = 1 / Σ比率²。定義はツールチップと F1）と、30% を超える業種の注意                                    |
| **損益寄与**         | 期間は**今日・今月・今年・取得来**（T で巡る）。**全銘柄**を大きい順に並べ、0 のところに区切りを入れる。多いときはカードの中で縦にスクロールする（↑ ↓ PgUp PgDn Home End。選んだ行が見える位置へ送る）。棒は 0 を中心に左右に伸ばし、値動き（上下の色）に**その期間に権利落ちした配当**（金色）を続けて積む。上に合計・うち配当・値上がりと値下がりの数・期間の定義。売った銘柄も、売った日（最後に記録した日）までの分を薄い行で出す（6.5）                                                                                                                                                                                                                                                                                                                                                      |
| **配当見込み**       | **今の月から 12 か月**の棒（権利落ちの月に積む）。中立の色で、次の月だけ金色。左隣に**前年同月**を細い棒（中立・半透明）で並べ、増えた月・減った月がひと目で分かる（破線の枠は「未確定」に見えるのでやめた）。図の高さは 180px まで。月の軸は「11月 12月 1月 …」にそろえる。額は**直近 1 年の 1 株配当（6.6）× 現在の数量**。年間（税引後）・**前年比**（円・%）・利回り（評価額と取得額に対して）。「入金は約 2〜3 か月後」と注記。配当カレンダー（`divcal`）と月の計算を共有する                                                                                                                                                                                                                                                                                                                |
| **今後 30 日の予定** | 上に**今日から 30 日の時間軸**（1 週ごとの目盛り）に点を打ち、近さと混み具合を先に見せる。点は権利付き最終日 = 金・決算 = 指標の青・アラート = 白抜きの輪（金と注意の黄は見分けにくいので形でも分ける）。同じ日は上に積む。下にカード（権利は**配当見込み額**を添える・決算（予定）・成立中のアラート。日付順）。カードを選ぶと点も大きくなる                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

### 4.2 配当の分析のカード

配当を厚く見せるための段。分類（業種・市場区分・種別・口座）でも集計する。

| カード                   | 中身                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **配当の内訳**           | **ドーナツ**（業種が既定。分類は銘柄・業種・市場区分・種別・口座）。大きい順に **5 つ＋「その他」**（灰色。凡例にも載せる）。色は**配当の金色の濃淡**（割合が大きいほど濃い。段の差を広げる。ライトは濁らない明るい金 `--f-gold-fill`。業種ごとに別の色相を振らない。11 色を超えて見分けられず、上下の色ともぶつかるため）。スライスの間は 2px あけ、大きいスライスには割合を中に書く（文字の色は背景から計算）。真ん中は年間の合計、行を選ぶとその分類の名前・割合・額。横に凡例を兼ねる一覧（色見本・額・割合・前年比。名前は切らない幅にする）。S の幅ではドーナツをやめ、一覧に横棒を出す。行を選ぶと、その分類の銘柄だけが他のカード（寄与・予定・表）で明るく残り、スライスが少し外へ出る                                                                                                                                                                                                                        |
| **年間配当（税引後）**   | 大きな数字で年間の見込み。**前年比**（円・%。1 年前の額を添える）。その下に**配当の見込みの推移**（記録の日ごとの「その日の数量 × その日までの直近 1 年の 1 株配当」。金の線と淡い面。段が増配・買い増し・売却の日。1 年前に破線）。2 列の区切りで: 月あたり・税引前・利回り・取得利回り・**NISA で非課税になる額**（NISA の口座の配当にかかるはずだった税）・受け取った累計（CSV の日付を添える）・**増配と減配の銘柄の数**・**上位 3 銘柄の割合**（配当の集中度）。下に**目標**（設定。任意。「月 5 万円」など）の進みを細い棒で                                                                                                                                                                                                                                                                                                                                                                                     |
| **増減要因（前年比）**   | ウォーターフォール: **1 年前 → 増配 → 減配 → 新規 → 買い増し → 売却 → 今**。増えた分は `--up`、減った分は `--down`、両端は中立。足すと「今」と一致する（6.6）。両端の棒は下を切り、切ったことを波線で示す（0 から描くと差が見えない）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **分類ごとの配当**（表） | 分類が銘柄以外なら**アコーディオン**: はじめは分類の行（小計）だけを並べ、→ で開いて銘柄を出し、← で閉じる（Enter・クリックでも開閉）。分類は内訳のカードと共有する。列: 銘柄・権利月・**年間（税引後）**（セルの中に割合の小さな金の棒）・**前年比**（セルの中に 0 を中心にした小さな棒）・**要因**（`増配 +7,920`・`買い増し +2.2万`・`新規`・`減配`・`一部売却`・`売却`・`据え置き` のラベル。額つき）・**1 株配当の 5 年**（小さな棒。最後の年は増配なら金、減配なら `--down`）・**増配率**（年率・4 年）・**連続増配**（5 年の範囲で。最大「4 年+」。増えていなくても減っていなければ「非減配」）・利回り・取得利回り・**配当性向**（概算。100% を超えたら「100% 超」のラベル）。S で並べ替え（年間・前年比・利回り・取得利回り・増配率）。売却した銘柄は前年比のマイナス分として薄い行で残す。見出しは固定し、本体は縦にスクロールする。狭い幅では権利月・配当性向・増配率・連続増配・取得利回り・要因の順に隠す |

ブラッシング: 配分のタイル・ドーナツの一覧の行・表の分類の行を選ぶと、同じ分類の銘柄だけが他のカードで明るく残り、ほかは薄くなる。

### 4.3 見た目

- **面**: カードは `--panel` の面に 1px の `--line`。角はアプリと同じ `--radius`（2px）。`kbd` もアプリと同じ平らな形。箱の中に箱を作らず、細い区切り（`--line-soft`）で並べる。影・すりガラスは使わない。ヒーローだけ、含み損益の符号の色を左上に薄くにじませる（ダークだけ。ライトではエラーの色に見えるので無し）。
- **数字**: アプリと同じ**等幅の書体**（`.num` = `--mono` ＋ `tabular-nums`）。本文は 12px（`--fs-2`）。太字は評価額・年間配当・各カードの主な値だけにし、表のセルは 400。評価額は 30〜46px、年間の配当は 26〜34px（ペインの幅で変える）。ラベルは 11px 以上（日本語は 10px では読みにくい。ラベルの中だけ 10px）。
- **色の意味は一つ**:
  - 上昇・下落・増えた・減ったは `--up` / `--down`。日本式が既定で、設定で米国式に変わる。±の符号を付け、色だけに頼らない。**▲▼ は使わない**（日本の会計では ▲ がマイナスを表すため、上昇の印に使うと逆に読まれる）。
  - 予定の種類は**形**で示す（◆ 権利 = 金・■ 決算 = 中立・○ アラート = 中立）。金色は権利だけ。決算に青系を使わない（下落の青に見えるため）。
  - 配当の表の「要因」は枠なしの文字にし、色は額だけに付ける（赤い枠のラベルが並ぶと列全体が赤く見える）。分類の行にも 5 年の 1 株配当（現在の数量）の小さな棒を出し、列の中ほどを空けない。
  - 口座の色（`--acct-*`）は**点と細い帯だけ**に使い、面を塗らない。NISA 成長の青が下落の青に、特定の琥珀が注意の色に見えるため。
  - **金色は配当**（寄与の配当の分・次の月・増配した年・目標）。配当の棒そのものは中立の色（`--f-bar`）。
  - 1 年前は**破線の枠**（塗らない）。
  - ドーナツは金の 1 色相の濃淡（割合の大きさ）。分類ごとの色相（カテゴリの色）は使わない。
  - 新しい分類の色は足さない（業種ごとに色を振らない。11 色を超えて見分けられないため、棒の長さと並びで見せる）。
- **動き**:
  - はじめの表示だけフェードする。キーを押すたびには動かさない。
  - 金額のカウントアップはしない。途中の値が誤った金額に見えるため。
  - 分類を変えたときは、タイルが前の位置から動く（FLIP）。
  - `data-reduce-motion` で止める。
- **用語**: 証券会社・投資アプリで通る言い方にそろえる。無理に和語にしない。
  - 使う: 前年比・前年同月・今後 12 か月・来月・月平均・取得来・年率・受取配当・配当見込み・最高値比・前回記録比・現金除く・時間加重収益率（概算）・試算・未起動日（補完）・値上がり / 値下がり・分類（業種・市場区分・種別・口座）
  - 使わない: まとまり・分け方・1 年前から・これからの・受け取った・当てはめ・開かなかった日・上げ / 下げ・札・めくる
  - 件数は分類の名前で数える（「11 業種」「5 口座」）。
- **状態**: 読み込み中（骨組み）・保有なし（取り込みの案内）・記録が始まったばかり（4 日以下は内訳の代わりに案内）を用意する（モックの帯のボタン）。配当の分析は、記録が 1 年に満たないと数量の要因を出せない（6.6）ので、そう書いたラベルを出す。

## 5. 資産推移の記録（毎日 1 回）

### 5.1 いつ記録するか

アプリは常駐しないので、「バックグラウンドで 1 日 1 回」は **Core の取得のジョブの終わり**に行う。アラートの判定と同じ `jobDone` の場所で、次の場合に記録する。

- **日々の更新・初回・全データの取り直しが成功して終わったとき**（種類で絞る。`jobDone` はすべての種類で呼ばれる）。取得失敗（`failed > 0`）があった日は、その点に `stale` を付ける。
- **保有を変えたとき**: `portfolio.save`・`applyImport`・`undoImport`・`applyCsv`・`applyHoldings` など、保有を書くメソッドすべて。その日の点を書き直す。
- **日付**: その時点で取引が終わっている最新の営業日（`calendar.ts`。日本時間の `YYYY-MM-DD`）。銘柄ごとの `asOf` には合わせない。
  - 取引時間中の値は `final: false`（暫定）で書く。次の記録で、その日が終わっていれば確定の値で**書き直す**。
  - 確定した点は上書きしない。保有を変えたその日だけは例外。
- **未起動日**: 次の記録のときに、前回の**保有（数量・取得単価）× その日の終値**で埋める（`src: 'fill'`）。保有はアプリの中では取り込み・編集のときしか変わらないので、「アプリが知っていた保有」としては正確。
- **分割**: 分割の日から CSV を取り込み直すまでの間は、終値は調整済みなのに数量は分割の前のまま。そのため `holdings.ts` の分割の調整を当ててから評価する（L3 のテスト）。過去の点の数量を読むとき（1 年前の数量・寄与）も、その後の分割で換算する。
- **読み取り専用のとき**（FR-S12）: 書かずに、ペインの見出しにそう出す。フリー 2〜4 の窓は読み取り専用。消すコマンドは `blockedInFree`。

### 5.2 記録の中身

```ts
interface FolioPos {
  code: string
  acct: AccountType
  qty: number
  cost: number
} // cost は平均取得単価
interface FolioPoint {
  d: string // 日付（JST。YYYY-MM-DD）
  src: 'rec' | 'fill' // 記録 / 未起動日を埋めた
  final: boolean // その日の取引が終わってからの値か
  stale?: boolean // 取得失敗のある日の値
  value: number // 評価額（円）
  cost: number // 取得額（円）
  pos: FolioPos[] // その日の保有（評価し直し・内訳・埋める値・1 年前の数量・寄与・売った銘柄に使う）
  realized?: number // 実現損益の累計（CSV。あれば）
  received?: number // 受取配当の累計（CSV。あれば）
  at: number // 書いた時刻（ms）
}
interface FolioHistory {
  version: 1
  points: FolioPoint[]
} // d の昇順。1 日 1 件
```

- 保有 30 件 × 10 年（約 2,500 日）で数 MB。上限は設けない。
- **再生成できないデータ**なので、アラートの状態と同じ扱いにはしない。
  - 置き場所: `<userData>/user/portfolioHistory.json`。
  - 書き方: 一時ファイル＋改名。直前の版を `.bak` に残し、読めないときは上書きせずに知らせる。
  - 世代のバックアップ（10 世代）には入れない。毎日書くと世代が押し流されるため。
- **書き出し・読み込み**の対象に入れる。読み込みは**日付で混ぜる**（記録 > 埋めた値、新しい `at` が勝つ）。丸ごとの置き換えにしない。保有と同じく、書き出しの前に個人の情報を含むと知らせる。
- 書き換えたら `user.changed` を全窓に配る（`src/core/changes.ts` の `CHANGES`）。
- **全データの削除（市場データ）では消さない**。記録を消すコマンド（確認つき）と、CSV への書き出しを用意する。

### 5.3 計算の置き場所

- `src/shared/folio.ts`（純粋な関数。L1 のテスト）:
  - 評価（`valuation()` を移し、指標の引き方を引数で渡す）
  - 集中度・寄与（期間・配当の分・売った銘柄）
  - 時間加重の概算・期間の内訳
  - 配当: 1 株配当の年（6.6）・増減の分解・分類ごとの集計・増配率・連続増配・配当性向・見込みの推移・月割り（`divcal` と共有）
  - ドーナツの「その他」のまとめ方・ウォーターフォールの段
  - ツリーマップの色の段と文字の色
- Core の `folio.series({ from, est })` と `folio.dividends()`:
  - 記録・埋めた値・試算（`est` のときだけ）をまとめた系列と内訳、配当の分析（銘柄ごとの 1 株配当の 5 年・1 年前の数量）を返す。
  - 過去の終値と配当は Core の DB から読む。`bars.many` の 60 件の上限を renderer で分けて呼ばない。
  - renderer は描くだけ。
- 推移のグラフ・ウォーターフォールは SVG で描く（帯の塗り分けに clipPath を使う。Lightweight Charts では帯を作れない）。

## 6. 正直に出すための決まり

### 6.1 記録の前（試算）

現在の保有で過去を試算した推移は、**今残っている銘柄（勝ち残り）を過去に延ばしたもの**で、実際の推移ではない。そのため次のように扱う。

- 既定では出さない。**E** で出す。
- 出すときは細い中立の線だけにする。面・取得額の線・損益のラベルは付けない。
- 区間の中に「現在の保有で過去を試算（参考。実際の推移ではない）」と書く。
- 見出しの値動き・期間の内訳・時間加重・ベンチマークの比較には**入れない**。
- 区間は、すべての保有の終値がそろう日から。

### 6.2 時間加重の概算

- 入出金 = 取得額の増減 − 実現損益の増減。売った利益を損と数えないため。
- 実現損益が両方の点に無いときは、そこで鎖を切る。
- 配当は含まない。
- 名前は「時間加重の概算（配当を除く・取り込みの日を入出金の日とみなす）」と書く。
- ベンチマークとの比較は、記録が 20 日貯まってから出す。
- 保有が 0 件になった日も鎖を切る。

### 6.3 NISA

CSV の取り込みは投資信託と外国株を飛ばすので、つみたて投資枠の多くは見えない。年間の枠（240 万・120 万）は、取引日が無いので出せない。そこで次のようにする。

- 「NISA 簿価（このアプリが扱う銘柄だけ）／生涯 1,800 万」の細い棒だけを出す。
- 使った割合（%）と「残り」は出さない。

### 6.4 配当の見込み

- 「直近 1 年の 1 株配当 × 現在の数量」と明記する。会社の予想ではないので、減配・増配は実際に権利落ちしてから反映される。
- 過ぎた月を「受け取った」ように見せない。今後 12 か月だけを出す。
- 支払月は推定しない。「入金は約 2〜3 か月後」と注記するだけにする。月は権利落ちの日の月（月末に確定する銘柄なら権利確定月と同じ）。

### 6.5 寄与

- **今日**: 前日比 × 数量。休日は最後の営業日の値で、日付を添える。
- **今月・今年**: 期間の初めからの**値動き＋その期間に権利落ちした配当**（権利落ちの日に持っていた数量 × 1 株配当・税引後）。配当を入れないと、権利落ちで値が下がる高配当の銘柄が不当に低く見えるため。
  - 数量は毎日の記録の `pos` から日ごとに取る。期間の途中で買った分は取得額から、売った銘柄は最後に記録した日の評価額まで（薄い行で「売却」）。
  - 期間の初めが記録より前のときは、記録の初日までを現在の数量で計算し、ラベルで「記録の前は現在の数量で計算（参考）」と出す。
  - 合計は、資産推移の同じ期間の「値動き＋受取配当（権利落ちの見込み）」とほぼ一致する（入出金を除く）。
- **全**: 取得から（含み損益）。取得日が分からないので配当は入れないと書く。
- 寄与の合計と資産推移の見出しを比べられるよう、上に合計を出す。

### 6.6 配当の分析

- **1 株配当の年**: カレンダーの 12 か月で切ると、権利落ちの日が数日ずれただけで 1 回分が入ったり抜けたりし、偽の増配・減配が出る。そこで**直近の権利落ち N 回の合計**を「直近 1 年の 1 株配当」とする（N は過去 2 年の年あたりの回数）。1 年前はその前の N 回、5 年はそれをさかのぼる。回数が変わった（年 1 回 → 年 2 回など）ときはラベルで知らせる。
- **増減の分解**（銘柄ごと。足すと全体の増減と一致する）:
  - 増配・減配 = 1 年前の数量 × （現在の 1 株配当 − 1 年前の 1 株配当）
  - 数量の要因 = （現在の数量 − 1 年前の数量）× 現在の 1 株配当。1 年前が 0 なら**新規**、増えたら**買い増し**、減ったら**一部売却**、今が 0 なら**売却**
  - 税は今の口座で計算する（口座を移した銘柄は、1 年前の点の口座を使う）
- **1 年前の数量**は毎日の記録の `pos` から取る（1 年前の日に最も近い点）。分割はその後の分割で換算する。**記録が 1 年に満たないあいだ**は、1 年前の数量を現在の数量とみなし、増減は増配・減配の分だけになる。そのことをラベルで「数量の変化は記録が 1 年貯まってから（それまでは増配・減配の分だけ）」と出す。
- **特別配当・記念配当**も 1 株配当に入る（区別できない）。前年の同じ回の 1.5 倍を超える回があれば「特別配当の可能性」のラベルを出す。
- **連続増配**は 5 年の範囲で数える（最大「4 年+」）。年ごとの 1 株配当が前の年より増えた年を数え、据え置きで止まる。減っていなければ「非減配」。
- **配当性向**は「利回り（実績）× PER（実績）」の概算と明記する。会社の発表の配当性向とは違うことがある。REIT・ETF には出さない。
- **目標**は利用者が設定する（任意。月あたりの額）。設定が無ければ出さない。
- **NISA で非課税になる額** = NISA の口座の年間の配当 × 20.315%。

## 11. 実装で決めたこと（2026-11-15）

- 計算の置き場所: 純粋な関数は `src/shared/folio.ts`（L1）、記録と市場データの組み合わせは `src/core/folio.ts`（`FolioBook`・`recordPoint` ほか）、画面のロジックは `src/renderer/lib/folio.ts`（L4）、文言は `src/renderer/lib/folioText.ts`。
- 記録の日の値: その日の日足の終値（分割調整済み）× 記録の株数 × その後の分割の倍率。その日の足が無い・暫定の足なら暫定（`final: false`）にし、次の記録で書き直す。保有が無くなった日は評価額 0 の点を残す（前の保有で補い続けない）。
- 記録のとき: 起動の直後（80ms 後）・日々の更新・初回・全データの取り直しの終わり・保有を書くメソッド（`portfolio.save`・`applyImport`・`undoImport`・`applyCsv`）。
- 記録の書き出し: 保有の JSON の `history`（[holdings-format.md](holdings-format.md)）。利用者のデータの一括の書き出し（`user.exportAll`）には入れない（保有と同じく個人の資産情報なので、保有の書き出しと一緒に扱う）。
- 記録を消す・配当の目標: コマンドバー（Ctrl+K）の「資産推移の記録を消す」（確認つき・1 枚目だけ）・「配当の目標（月あたり）を決める」（設定の `divGoal`）。
- 1 年前の株数: 記録の 1 年前の日に最も近い点（補完値を含む）。
- 実装のレビュー（Opus 5.5）で直したこと:
  - 前の日までの暫定の点（足がそろっていなかった記録・補完値）は、次の記録でその点の保有のまま確定の値に書き直す。
  - 補完は銘柄ごとに日足を 1 回だけ読む（長く起動しなかった後でも Core を止めない）。
  - 記録を消すときは `portfolioHistory.cleared-<時刻>.json` に、読めない本体は `portfolioHistory.broken-<時刻>.json` に退避する（.bak を押し流さない・上書きしない）。読めない本体を退避して .bak から読んだときは、見出しに知らせる。
  - 保有の取り込みを元に戻すと、混ぜた資産推移の記録も戻す。記録だけの保有の JSON も取り込める。
