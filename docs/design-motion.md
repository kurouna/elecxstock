# ペインの最大化とタブの切り替えの動き（設計）

FR-L3（1 ペインの最大化と戻す）と FR-V9（動きは情報を速く読ませる目的に限り控えめに。OS の「アニメーションを減らす」と設定の「動きを減らす」に従う）の範囲で、
最大化・戻す・タブの切り替えに動きを付ける。投資家・企業向けの道具なので、光・揺れ・行き過ぎ（オーバーシュート）・幕は入れない。
動きの目的は「どのペインが広がったか・どこへ戻ったか」「どちらのタブへ移ったか」を目で追えるようにすることだけ。

## 1. 最大化と戻す（Ctrl+Shift+Enter・Esc）— `src/renderer/lib/paneMax.ts`

- **FLIP を Web Animations（`el.animate`）で**: 前の矩形を測る → `app.maximized` を変えて `flushSync()` → 後の矩形を測る →
  前の矩形に見える transform から `none` へ。広げるときも戻すときも同じ流れで、終わりは必ず本当のレイアウトになる
  （戻す間だけ固定表示を続ける状態・`animationend`・予備のタイマーを持たない）。`flushSync` を使うので、キー・クリックのイベントから呼ぶ（`$effect` の中からは呼ばない）。
- **大きさは動かさない**: チャート・グリッドのタイル・ヒートマップは `ResizeObserver` で描き直すので、transform だけを動かす（描き直しは 1 回）。
- **動きを 2 つに分ける**（`MAX_IDS`）: transform だけの `pane-max` と、前に出す・影の `pane-max-lift`（同じ時間・一定の値）。
  1 つの効果に z-index・box-shadow を混ぜると Chromium は効果ごとメインスレッドで動かし、最大化の直後のチャートの描き直しと同じフレームでカクつくため。
- **フォーカスの枠を消さない**: 影は今の `box-shadow`（`.pane.focused` のキーのフォーカスの枠）に足す（`liftShadow`）。キーボードで操作しているペインの枠が飛んでいる間も見える（FR-KB3）。
- **表示倍率**: `getBoundingClientRect` は倍率が掛かった px、transform の translate はルートの `zoom` の中で倍率が掛かるので、差は `rootZoom()` で割る（比は割らない）。
- **途中の操作**: 飛んでいる途中のトグル・Esc は、止める前に今の見た目の矩形を測るので、その場から折り返す。別のペインへ最大化を移すときは、前のペインは一度で戻す。
- **一度で切り替える**: 動きを減らす（設定 `reduceMotion`・OS）・ペインが DOM に無い・面積 0 のとき。
  `revealPane` は、見せるのがドロワーの中のペインなら `clearMaximized()`（ドロワーが開く動きと重ねない）、本体のペインなら `setMaximized(null)`（どこへ戻ったかを見せる）。
  最大化したペインを閉じる・ドロワーへ移す・動かすときは、`layout.svelte.ts` が最大化の状態を消す（`dropMaximized`。残ると次の Esc が空振りする）。
  レイアウトを初期状態に戻す（`resetLayout`・`resetAllLayouts`）ときも消す（`resetAllLayouts` はマイレイアウトのページを書き換えないので、マイレイアウトを表示中なら消さない）。
  分割・まだ無いペインを開く（`focusNew`）ときは、木が変わったあとに `setMaximized(null)` で新しい場所へ戻す（分割で新しい分割に包まれてペインの要素が作り直されたときは、新しい要素を飛ばす）。ドロワーを開く・ピン留めする（`toggleDock`・`pinDock`）ときは
  `clearMaximized()`（最大化したペインの z-index 30 がドロワーの 20 を覆い、結果が見えないため。開く動きと重ねない）。
  タブ・ページの切り替えはペインごと作り直すので、`layout.svelte.ts` が動きなしで消す。
- 時間は app.css のトークン（`--motion-max` 150ms・`--motion-restore` 120ms・`--ease-out`）を `getComputedStyle` で読む。動きを減らすときはトークンが 0ms になり、飛ばさない。

### グリッドのタイルの大きさ

`gridDraw.ts` の `drawTile` は canvas の大きさを `getBoundingClientRect` で決めていたので、最大化の瞬間に走る `ResizeObserver` が
transform の掛かった（縮んだ）矩形で描き、着地後もぼけたタイルが残る。transform の掛からない CSS の幅（`getComputedStyle`。`clientWidth` と違い小数を丸めないので、
高 DPI で 1 デバイス px ずれない）× `rootZoom()` に替えた（`tileSize`・`cssPx`）。ポインタの足の選択は今までどおり `getBoundingClientRect` の px で、止まっているときは同じ値になる。

## 2. タブの切り替え — `src/renderer/lib/ink.ts`・`playIn`

- **下線を 1 本にして、選んだタブへ滑らせる**（`transform`・`width`）。レイアウトのタブ（TopBar の `.presets`）とドロワーのタブ（Dock の `.tabs`）。
  マイレイアウトはタブと ▾ の 2 つのボタンにまたがる（`inkSpan`）。
  - 滑らせるのは選んだタブ（`key`）が変わったときだけ。ボタンの幅が変わって測り直すとき（ページ名・言語・狭いときの省略 FR-L13・文字の読み込み）は滑らせない。
    レイアウトのタブの `key` は `layout.doc.active` だけ（ページを替えた・名前を変えたときは、幅を置き直すだけ）。初めて出すときも滑らせない。
  - 滑っている途中に測り直す（文字の読み込みなど）ときは、滑りを保つ（途中で飛ばない）。
  - 子は増えたり作り直されたりする（ドロワーのタブ・▾）ので、測るたびに `ResizeObserver` で見直す。
  - 見せるときは inline の `visibility` を外すだけにする（閉じたドロワーの `visibility: hidden` を打ち消さない）。
  - 測るのは `offsetLeft`・`offsetWidth`（倍率が掛かっていない px）なので style の px とそろう。入れ物は `position: relative`。
- **中身が入ってくる動き**（`playIn`・`slideDir`・`enterFrames`）: レイアウトのタブ・マイレイアウトのページを替えたら作業域（Workspace の `.main`）に、
  ドロワーのタブを替えたら出てきた `.slot` に、Web Animations で一度だけ再生する。
  - 透明から始めない（不透明度 0.3 から）。作り直しのあとに中身が読めるまでを遅らせないため。
  - タブの並びで右へ移ったら右から 16px、左なら左から（Material の shared axis X と同じ向き）。マイレイアウトのページどうしは滑らせずに出すだけ。起動したとき・初めて出すときは動かさない。
  - **連打**: 前の動きの途中なら薄くし直さず、滑らせるだけにする（作業域が明滅しない。ドロワーは前のタブの slot も探す `scope`）。
  - 終わったら何も残さない（`fill` なし）ので、`.main` に transform・opacity は残らない。
  - 動きの途中は `.main` に transform が掛かり `.maxed`（`position: fixed`）の基準がずれるので、`setMaximized` は先にこの動きを終わらせる（`finish()`）。
- **ドロワー**（Dock.svelte・`drawerSlide`）:
  - Dock のコンポーネントはレイアウトのタブをまたいで使い回され、`dock` だけが別のタブのドロワーに替わる。持ち主（`identity(dock)`）が替わったら、
    中身も下線も初めて出したのと同じに扱う（滑らせない。ink の `group`）。
  - 比べるのは番号ではなくペインの ID。前のペインを外して番号が詰まっただけなら動かさない。前のペインがもう無いときも動かさない。
  - ドロワーが開いて落ち着いてから（開いた次のフレームから）だけ動かす。閉じた状態からタブを選ぶと、開く動きと重なるため（下線も ink の `slide: false`）。
  - Ctrl+Tab・Ctrl+Shift+Tab は、押した向き（`setTabHint`）で入れる。端で折り返しても向きを保つ。
  - 中身が滑り込む間も枠の外（本体の上）へはみ出さないよう、`.body` は `overflow: clip`（hidden と違いスクロールの入れ物を作らないので、動きの途中の focus で中身がずれない）。
  - 下線は、持ち主が替わった・閉じているときは、滑っている途中でも滑りを保つ時間を捨てる。同じフラッシュの update はまとめて 1 回だけ測り、滑らせるかは最後に置いたときの key・group と比べて決める（届いた順番によらない）。隠すときは滑りも消す。

## 3. 時間

| 動き             | トークン           | 時間  | イージング    |
| ---------------- | ------------------ | ----- | ------------- |
| 最大化（広がる） | `--motion-max`     | 150ms | `--ease-out`  |
| 戻す             | `--motion-restore` | 120ms | `--ease-out`  |
| タブの下線       | `--motion-tab`     | 200ms | `--ease-view` |
| タブの中身       | `--motion-view`    | 200ms | `--ease-view` |

- `--ease-out` は `cubic-bezier(0.2, 0.8, 0.2, 1)`（ドロワーの開閉と同じ減速。Dock.svelte もこのトークンを使う）。`--ease-view` は `cubic-bezier(0.2, 0, 0, 1)`。
- タブの切り替え（下線と中身）は FR-V9 の 150ms の例外として 200ms。下線と中身を同じ時間・同じイージングにして、ひとつの動きに見せる。
  `--ease-out` のままだと最初の 1 フレーム（17ms）で 6 割進み、目に見えて動くのは初めの 50ms ほどだった（実際のアプリで 1 フレームずつ測った）。

## 5. 経緯

- 最初の案（戻す間だけ固定表示を続ける状態・背景の幕・タブの中身のフェードと 6px のスライド・ドロワーのフェード）を Fable 5.2 にレビューしてもらい、
  状態が多い・終わりで「ぱちっ」と切り替わる・幕は見える時間が短く装飾に近い・`{#key}` の入れ物の transform が `.maxed` を壊す・グリッドのタイルが縮んで描かれる、
  の指摘を受けて今の形にした。
- 下線だけではタブを替えたことがわかりづらいという利用者の意見で、中身の動きを控えめな形で戻した。それでもわかりにくいという意見で測ったところ始めに偏りすぎていたので、
  イージングを替え、16px・200ms にした（200ms は利用者が選んだ FR-V9 の例外）。
- 実装を Fable 5.2 と Opus 5.5 にレビューしてもらい、次を直した: 最大化の動きを transform だけにする・フォーカスの枠を残す・使い回されたドロワーの動き・
  閉じたドロワーで動きが重なる・連打の明滅・Ctrl+Tab の折り返しの向き・下線の子の監視と `visibility`・ページ名で下線が滑る・下線と中身の時間とイージング・
  最大化したペインを閉じても状態が残る（前からの不具合）・タイルの幅の丸め・撮影とテストの待ち。
- 直さなかったもの: 飛んでいる 150ms の間の矩形（方向でフォーカスを動かす・区切り線のドラッグが transform 込みの矩形を見る。実害はほぼ無い）。
  戻すときに小さく描いた中身を拡大して始めるので一瞬ぼける（120ms で、大半は最初の数フレームで進む）。気になるなら枠だけの代わりの要素を飛ばす方式に替える。
  動きを減らす設定のときに、滑らせず短いフェードだけにする案（今は動きを一切止める）。
- 外部の静的レビューと Opus 5.5 の再レビューで、下線の滑りを保つ時間の後始末・レイアウトを戻すときの最大化・ドロワーのはみ出し・最大化中の分割・ペインを開く・ドロワーを開く、
  を直した。ドロワーをマウスで開く経路（帯・タブ・ドロップ・ピン）は、最大化したペインが帯ごと覆って手が届かないので通していない（キーの経路だけ `clearMaximized`）。
  最大化を解いてドロワーを開いたあと閉じても、最大化には戻さない（最大化は一時的な見方なので）。
