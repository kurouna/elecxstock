# マイレイアウト（フリーのタブを複数のページに）の仕様・設計

状態: 決定（第 3 版、2026-11-16）。第 1 版を Opus 5.5 と Fable 5.2 のレビュー（既存コードと突き合わせ）で直し（§10）、第 2 版をもう一度のレビューで直した（§11）。移行の処理をやめ、読み損なったら既定に戻す形にし（§12）、その方針のレビューで直した（§13）。§9 は決めた。要求は requirements.md の FR-L14。未実装（§8 の段階 1 から）。

## 1. 方針

- フリーのタブ（Ctrl+Shift+8）を、**利用者が名前を付けて増やせるページの入れ物**にする。Market Speed 2 のマイページのように、自分専用の画面を何枚も持てる。
- タブは増やさない。トップバーの幅（FR-L13）を取らないように、フリーのタブの横に **▾ のボタン** を付け、そのメニューでページを選ぶ・足す・名前を変える。
- 今の **名前を付けたレイアウト（FR-L4 の P2、Ctrl+Shift+L）はマイレイアウトに統合する**（利用者の決定）。「読み込むためのスナップショット」と「開いて使うページ」の 2 つを持たない。
- 2 枚目以降のウィンドウ（フリー 2〜4）は別の概念のまま。開くときの初期の形に **マイレイアウトのページを選べる**（写しを開く）。
- **既存の作りをなるべく変えない**: 表示中のページは今と同じ `entries.free` に置く（§5.2）。分割・移動・ドロワー・フリー N の関数はそのまま動く。

## 2. 言葉

| 言葉                      | 指すもの                                                                          |
| ------------------------- | --------------------------------------------------------------------------------- |
| マイレイアウト（タブ）    | 1 枚目の 8 番目のタブ（英語は Pages）。今の「フリー」のタブの名前を変える（§9-1） |
| ページ                    | マイレイアウトの中の 1 枚。名前・レイアウト（本体の木とドロワー）を持つ           |
| フリー 2〜4（ウィンドウ） | 2 枚目以降の窓。名前は変えない（「フリー」は窓だけの言葉になる）                  |

## 3. 振る舞い

### 3.1 タブとメニューのボタン

- タブは「マイレイアウト · <ページ名> [8]」と、その右の **▾ のボタン**（タブのボタンとは別。押せるのでドラッグから外す）。
- ページ名は **表示中のタブのときだけ** 出し、CSS の `max-width` と省略記号で切る（コンポーネントで文字数を切らない）。全体はツールチップに出す。
- タブを押すとマイレイアウトへ（最後に開いていたページ）。▾ を押すとメニューをタブの下に開く。
- FR-L13: タブが長くなるので、省く段の境目（今の 1479・1319px）を日英・文字の大きさで測り直す。タブの名前を省く段でページ名も省く（▾ とキーの数字は残す）。

### 3.2 メニュー（ページの一覧）

```
  ✓ 朝のチェック          1
    決算                  2
    REIT                  3
  ─────────────────────────────
  ＋ 新しいページ                 Insert
  ⧉ このページを複製               Shift+Insert
  ✎ 名前を変更                    F2
  ↓ 今のタブを写してページに足す
  🗑 削除                         Delete（2 回）
```

- キー: ↑↓ で選ぶ・Enter で開く・Alt+↑↓ で並べ替え・Esc で閉じる。**1〜9** でその番号のページを開く（`KeyboardEvent.code` で判定し、変換中は無視する。FR-KB5）。10 枚目からは番号なし。
- メニューを開いたまま Ctrl+Shift+8・Ctrl+Shift+L を押すと閉じる（F1 と同じく、開いているオーバーレイを閉じる側に足す）。
- **新しいページ**: 初期の形（§3.4）を選ぶ → 名前を打つ。オーバーレイは 1 枚なので、今の `Layouts.svelte` と同じく、ダイアログのあとメニューに戻る。
- **複製・今のタブを写して足す**: ペインの ID を振り直して写す（§5.3）。「今のタブを写して足す」は、ほかのタブ（MTF など）でメニューを開いたときに出す。これが名前付きの保存の「保存」の代わり。写したあとは **新しいページを開く**（マイレイアウトのタブへ移る。写した元のタブは変えない）。
- **削除**: 最後の 1 枚は消せない（初期状態に戻す FR-L10 を案内する）。消したあと 10 秒間は「元に戻す」（Ctrl+Z）を出す（FR-L9 と同じ作り）。
  - Ctrl+Z は、メニューを開いているときはメニュー自身の `onkeydown` で拾い、閉じたあとは全体の `undo` で拾う。
  - 「元に戻す」は **最後の 1 つだけ** を持つ（サイズを戻すとページの削除は同じ枠。あとから行ったほうが残る）。取り込み・取り込みの取り消しで消す。
- **開けないページ**（`savedLayoutSchema` には通るが、`normalizeEntry(entry)` が `null` になるもの）は隠して、ファイルにはそのまま残す（§5.4）。一覧・コマンドバー・フリー N の初期の形には出てこない。
- ページの数の上限は 30。上限は **足す操作だけ** に効かせる（取り込みで超えたときは、そのまま全部を持つ）。`user.saveLayouts` のスキーマの上限は今の 200 のまま（30 で切らない）。

### 3.4 新しいページの初期の形

`shape` に、作ったときの形を持つ。FR-L10 で戻す先になる。

| `shape`             | 中身                                                     |
| ------------------- | -------------------------------------------------------- |
| `preset:free`       | 今のフリーのプリセット（`presetEntry('free')`）          |
| `free:empty`        | チャート 1 枚（`freeShape('empty')`）                    |
| `free:quad`         | チャート 4 枚                                            |
| `free:grid`         | チャートグリッド（このグリッドの銘柄、空から）           |
| `free:detail`       | マルチ時間軸 + 銘柄情報                                  |
| `preset:<PresetId>` | 「今のタブを写して足す」で写したページ（写した元のタブ） |
| なし                | 前の版の名前付きレイアウト・0 枚のときに作ったページ     |

### 3.5 ページの中

- 今のフリーのタブと同じ。どの種類のペインも置け、ドロワーも使える。変更は自動で保存する（FR-L4。上書きの操作は無くなる）。
- ページを替えたら、タブを替えたとき（`setPreset`）と同じく `dockOpen`・`maximized`・`focus` を空にし、そのページの最初のペインにフォーカスする。Workspace.svelte は 2 か所を、ページの ID でも走るようにする（`viewKey = active === 'free' ? 'free:' + page : active` を 1 つ作って両方で使う）:
  - 冒頭の `$effect`（フォーカス）。
  - 本体の `{#key layout.doc.active}`（61 行目）。これが無いと、ページを替えても木が作り直されず、コンポーネントの中の状態が前のページのまま残る。
- **サイズを元に戻す（FR-L9）**: 区切りの比率とドロワーの幅の基準を、次の順で探す。
  1. `shape` が `preset:<PresetId>` なら、まずそのプリセット。
  2. 似た区切りが無いとき・`shape` が無いときは、**すべてのプリセット** から（今の `defaultSizesOf` の候補を広げる）。違うプリセットの、同じペインの組の区切りに誤って合わないように、1 を先にする。
  3. `free:*` と `preset:free` は、今と同じくフリーのプリセット。
  - ドロワーの幅も同じプリセットから取る（`resetSizes`・`sizesAtDefault` は今、`presetEntry(active)` の `docks` を見ている）。
  - 元に戻す（`undoSnap`）はタブとページの ID の両方で照合する。
- **初期状態に戻す（FR-L10）**: 表示中のページだけを `shape` の形に戻す（`shape` が無ければ `preset:free`）。確認と完了の通知にはページ名を出す（`doResetLayout` は今 `preset.<active>` の名前を出す。§3.6 のフリー N の分岐も要る）。**すべてのタブを戻す** ときは、マイレイアウトのタブ（すべてのページ）に触らない。利用者が作ったものなので。

### 3.6 フリー 2〜4 でページを開く

- 新しいウィンドウ（Ctrl+Alt+N）の初期の形の選択肢に、マイレイアウトのページを足す（前回の配置・グリッド…の下に「マイレイアウト: <名前>」）。
- 開くのは **写し**（ペインの ID を振り直す）。フリー N で変えてもページは変わらない（同じページを 2 つの窓で書き換えると衝突するため）。
- 開く前に `flushLayoutSave()` を待つ。待たないと、400ms 前の保存されていないページが写る。
- フリー N に置けないペイン（一覧など）はチャートにし、ドロワーは捨てる（今の `freeDoc` と同じ）。変えたものがあればトーストで知らせる。ページが消えていたらグリッドで開き、トーストで知らせる。
- フリー N で初期状態に戻す（FR-L10）: ページから開いた窓は、そのページの今の中身を写し直す（ページが無ければグリッド）。
  - 今の中身は `user.load` で読み直すので、非同期になる。今の `resetLayout()` は同期の関数なので、ページを読むのは呼ぶ側（`doResetLayout`、もともと async）で行い、`resetLayout(entry?)` に渡す。
  - 確認と完了の通知には、タブの名前（`preset.free`＝マイレイアウト）ではなく **窓の名前**（「フリー 2」）を出す。ページから開いた窓なら「フリー 2（<ページ名> から）」。

## 5. データ

### 5.1 保存先と形

ページは **利用者が作ったもの** なので `layouts.json`（書き出し・取り込み・FR-S12 の保護の対象）に置く。名前付きのレイアウトは **もともと同じファイル・同じ形** なので、そのままページになる。

```ts
// layouts.json（savedLayoutSchema に shape を足すだけ。前の版の zod は知らないキーを捨てるので読める）
interface MyPage {
  id: string                         // 'p' + 時刻 + カウンタ（同じミリ秒に何件作っても重ならない）
  name: { ja: string; en: string }
  entry: LayoutEntry
  links: Record<string, InstrumentId> // 使わないが {} を書き続ける（前の版は必須で、無いと読み取り専用で起動するため）
  shape?: string                     // §3.4
  created: number
  updated: number
}
// layout.json に足す
interface LayoutDoc {
  ...
  page?: string                      // 表示中のページの ID（無ければ先頭）
}
```

- **前の版で開いても壊れない**: `links` は必須のまま書く。`shape` と `page` は前の版が捨てるだけ。前の版では、ページは「名前を付けたレイアウト」として見える。

### 5.2 表示中のページは `entries.free`（作業用の写し）

- `layout.json` の `entries.free` は今のまま **表示中のページの作業用の写し**。分割・移動・ドロワー・FR-L9・フリー N（`freeDoc`・`flushLayout`）は今の作りのまま動く。
- `LayoutState` に `pages: MyPage[]` を持つ。`app.layouts` は廃止して、ここに 1 本化する。
- **ページを替える**（`setPage(id)`）: `entries.free` を今のページの `entry` に写して戻し、新しいページの `entry` を `entries.free` に写す。そのあと §3.5 の後始末をする。
- **正は `layouts.json`**: `entries.free` はいつもページから作る写しで、ページより新しいことは無い。起動・取り込みと取り消しのあとの読み直し・ページの切り替えのたびに `entries.free ← page.entry` とする。`layout.json` の `entries.free` をページに採ることは無い（§5.4 の 0 枚のときを除く）。
  - こうしないと、`page` が見つからないとき（前の版が `layout.json` を書いた・取り込みで同じ ID のページが来た）に、先頭のページを別の中身で黙って上書きする。
- **保存**（`flushLayout`）: 表示中のページの `entry` を `entries.free` から写して、**毎回** `user.saveLayouts` → `user.saveLayout` の順に送る。同じ内容なら Core が書かずに済ませる（userstore.ts の `save` は前と同じ中身なら書かない）ので、「書いていない変更」の印は持たない。表示中でないページの変更（§5.7）もこれで保存される。閉じるときの flush は両方を待つ。この順なので、2 つの書き込みの間で落ちても `layouts.json` のほうが新しい。
- **書き出し・バックアップの前に flush する**: `exportUser`（と、利用者のデータを読む `backupDb`）は、先に `flushLayoutSave()` を待つ。待たないと、400ms 以内の変更が書き出しに入らない。
- **起動時の表示中のページ**: `page` の ID の開けるページ。無ければ先頭の開けるページ。開けるページが 1 枚も無ければ、§5.4 の決まりで 1 枚作る。
- **前の版から戻ったとき**: 前の版が `layout.json` を書くと `page` が消えるので、先頭のページを開く。前の版でフリーのタブを変えた分（`entries.free`）は採らない（ベータ版なので、行き来の分は守らない）。
- `entries.free` 以外のプリセットの保存は今のまま。

### 5.3 ペインの ID

- ペインの ID は、すべてのページと 9 つのタブをまたいで一意にする。そうしないと `app.focus`・`app.maximized`・`registerPane`、Svelte の keyed each が別のページのペインを指す。
- 写すとき（複製・今のタブを写して足す・フリー N で開く）は、ID を振り直す純関数（`cloneEntry`）を通す。ドロワーへ移す前の位置（`_home.sib`）も、新しい ID に直す。
- 読み込むとき（`normalizeDoc` とページ）は、`seen` を 1 つにして全部に通す。

### 5.4 読み込みと、読み損なったとき（移行の処理は持たない）

ベータ版で、フリーのタブを作り込んでいる利用者はまだ少ない。そこで **移行の処理も、移行済みの印（ファイル・キー）も持たない**。読めないものは既定に戻す。決まりは次の 3 つだけで、どれも何度通しても同じ結果になる。

1. **名前付きのレイアウトは、そのままページ**（同じファイル・同じ形なので、何もしない）。
2. **開けるページが 0 枚なら 1 枚作る**: 今の `entries.free`（`normalizeDoc` を通したもの。無ければフリーのプリセット）から、**ID が `free`**、名前「フリー」/「Free」のページを作る。
   - 名前付きのレイアウトを持っていない利用者は、今のフリーのタブがそのまま 1 枚目のページになる。持っている利用者は、名前付きのレイアウトがページになり、今のフリーのタブの中身は採らない（移行の印が無いので「初めての起動」を見分けられない。ベータ版なので受け入れる）。
   - ID を固定するので、読み取り専用で書けずに起動し直しても同じページになり、フリー N の `page:free` も変わらない。0 枚かどうかで決めるので、`free` を消しても生き返らない（ほかのページがあるため）。
   - 削除では最後の 1 枚を消せないので、0 枚になるのは「初めて新しい版で開いたとき」と「読み損なって既定に戻したとき」だけ。
   - 置き場所は **renderer の純関数**（1 枚目だけが呼ぶ。`normalizeEntry` が renderer にあるため）。L1 で試す。読み取り専用での特別扱いはしない（書けなければ Core が保存を断り、§5.5 のトーストが 1 回出るだけ。読み取り専用は、ほかのファイルを後から読んだときに立つこともあるので、起動時の `readOnly` で分けても当てにならない）。
3. **開けないページは隠して、そのまま書き戻す**: スキーマには通るが `normalizeEntry(entry)` が `null` になるページ（実際には、知らないペインだけのページ。新しい版で作ったページを前の版で開いたときなど）は、一覧・コマンドバー・フリー N の初期の形・表示中のページに出さない。`pages` には中身のまま持ち、保存でそのまま書き戻す（消えない）。件数を 1 回トーストで知らせる。
   - 捨てると、世代は直近 10 個しか残らず起動のたびに増えるので、新しい版と行き来するうちに消える。
   - 数の上限（30）と最後の 1 枚の判定は、開けるページだけで数える。

**ファイルごと読み損なったとき**:

- 今の FR-S12 は、どのファイルでも退避して **利用者のデータ全体を読み取り専用** で起動する。レイアウトの 2 つのファイルだけ、これを緩める: **ファイルを `backups/*.broken-*.json` に退避し、既定（`layout.json` は `defaultDoc()`、`layouts.json` は `[]`。そのあと 2 の決まりで 1 枚作る）で起動して、書ける状態を保つ**。レイアウトが読めないだけで、ウォッチリスト・保有・アラートまで保存できなくなるのを避ける。
  - `layout.json` のスキーマは `z.unknown()` なので、当たるのは JSON として読めないときだけ（形の違いは `normalizeDoc` が既定で埋める）。
  - `layouts.json` は **要素ごとに** `safeParse` する（今は配列全体で、1 件が通らないだけでファイルごと退避になる）。通らない要素だけを除き、元のファイルを間引かれない名前（`backups/layouts.dropped-<時刻>.json`）に写してから続ける。JSON として読めないとき・配列でないときは、ファイルごと退避して既定。
- **退避に失敗したら読み取り専用**: 今の `load` は rename の失敗を無視している。書ける状態のまま起動すると、次の保存で壊れたファイルを上書きし、元は世代に 1 つ残るだけになる。rename に失敗したら copy し、copy も失敗したら今のとおり読み取り専用にする。
- **新しい版が書いたファイル**（`version > STORE_VERSION`）は退避も既定もせず、読み取り専用にする（今の `migrate` は版を見ていない）。前の版で開いたときに、新しい版のデータを作り直さない。これはすべてのファイルに当てはめる。
- ほかのファイル（ウォッチリスト・スクリーン・保有・設定・アラート）は今の FR-S12 のまま（読み取り専用）。
- **知らせ方**: Core の `UserStore` に `recovered: { file, backup, dropped? }[]` を持ち、`user.load` で返す。1 枚目の窓だけがトーストで、レイアウトを既定に戻したこと（または除いた件数）と、退避したファイルの場所を知らせる。今の `error` は 1 本で後の失敗が上書きし、renderer は `userError` を画面に出していない（ステータスバーの「読み取り専用」だけ）ので、これとは別にする。
- 退避ファイル（`*.broken-*`・`*.dropped-*`）も、種類ごとに直近 10 個まで残す（今は間引きの対象外で溜まり続ける）。
- 実装: `UserStore.load` の失敗の分岐。L3 で試す（壊れた JSON・知らない形・通らない要素が混ざったファイル・rename の失敗・新しい版のファイル・読み取り専用）。

### 5.5 世代と保存の頻度

- 今の世代の間引き（10 分に 1 世代）は `layout` だけ。`layouts` は、**ページの中身だけが変わった保存** は同じく間引く。
- **ページの ID・名前・並びが変わる保存**（足す・消す・名前・並べ替え・取り込み）は、必ず世代を残す。見分けるのは Core で、前の内容と ID・名前の並びを比べる。
- 保存に失敗したとき（読み取り専用など）は、自動保存のトーストを 1 回だけ出す（今は失敗のたびに出る）。
- 合計の大きさの上限は 2MB（グリッドの銘柄などでページは大きくなりうる）。
  - 調べるのは renderer の **足す・複製・写す** の操作だけ。超えるなら足さずにトーストで知らせる。
  - **自動保存は大きさで断らない**（Core のスキーマにバイト数の上限を入れない）。断ると、`layout.json` だけ通って `layouts.json` とずれ、利用者は保存できていないことに気づきにくい。編集で 2MB を超えたときは、超えたことを 1 回だけトーストで知らせる（保存はする）。

### 5.6 取り込み・取り込みの取り消し

- 書き出しは今のまま（`layouts` にページが入る）。取り込みは **置き換え**（今と同じ）。
- **取り込みと取り消しの前に** `flushLayoutSave()` を待ち、読み直すまで保存を止める（`importAll` を待つ間に 400ms の保存が走ると、取り込んだページを古いページで書き戻す。最後の編集が取り消し用の記録（`preimport`）にも入らない）。
- 取り込みと取り消しのあとは、`pages` と表示中のページを読み直し（§5.2 の `entries.free ← page.entry`）、§5.4 の決まりを通し（0 枚なら 1 枚作る）、`focus`・`maximized`・`dockOpen` を空にしてから保存を再開する。これを 1 つの関数にする（`reloadUser` から呼ぶ）。
- 取り込むファイルに `layouts` が無いときは、`layouts` の取り消し用の記録を作らない（今の `importAll` は 5 つとも記録するので、取り消すと、取り込んでからのページの変更が消える）。
- 古い書き出し（`links` あり・`shape` なし）もそのまま読める。

### 5.7 `entries` を回る処理

`layout.doc.entries` を回る処理は、表示中でないページにも効かせる。例えば `removeScreen`（screens.ts:113）は、消したスクリーンを指すスクリーナーのペインを直す。`allEntries()`（9 つのタブ + 表示中でないページ）を作り、それを回す。実装のときに `doc.entries` を検索して漏れを無くす。

- 保存: `removeScreen` は `patchState` を通すので、今も `saveLayout()` が呼ばれる。flush は毎回 `saveLayouts` も送る（§5.2）ので、表示中でないページの変更もそのまま保存される。

### 5.8 Core・main・マルチモニタ

- `user.saveLayouts`・`user.saveLayout` は **1 枚目だけ** にする（dispatch.ts に足す。今は renderer の `blockedInFree` の約束だけ）。
- `CHANGES` には足さない（自動保存のたびに全窓へ配ることになる）。フリー N は、開くときに `user.load` で読むだけ。registry の changes のテストに除外の理由を書く。
- main の `SHAPES`（main/index.ts:474）は許可リストなので、`page:<id>`（`^page:[\w-]{1,40}$`）を足す。足さないと黙って捨てられ、前回の配置で開く。
- フリー N の窓の配置（`windows[slot]`）に、開いた元の形（`origin`。`free:grid`・`page:<id>` など）を持つ。FR-L10 で戻す先にする。
  - 形は **`LayoutEntry` のまま、直下にオプションの `origin?: string` を足す**（`{ entry, origin }` のように包まない）。前の版の `freeDoc` は `normalizeEntry(saved)` で `saved.root` を読むので、包むと前の版で窓の配置が消える。前の版は `origin` を捨てるだけ（そのあと戻すとグリッドになる）。
  - 今の `normalizeEntry` は `{ root, docks }` だけを返して `origin` を落とすので、`freeDoc` で `origin` を別に読み、保存（`flushLayout` の `saveWindowLayout`）で付け直す。
