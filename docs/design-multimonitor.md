# マルチモニタ対応の仕様・設計

状態: 実装済み（第 3 版。段階 R1〜R4、v0.0.5）。第 2 版（Fable 5.2 のレビュー反映）を、利用者の提案「2 枚目以降はタブなしのフリーだけ」に合わせて組み直した。`docs/design-p3.md` §8「別ウィンドウ（FR-L7）」を具体化する。

## 1. 方針

- 2 枚目以降のモニタは **チャートをたくさん並べる場所**。常時の監視画面ではない（データは終値ベース）。
- 2 枚目以降のウィンドウは **タブなしの「フリー 2」「フリー 3」…だけ**。1 枚目（今のアプリ）とは **疎結合**: 一覧（ウォッチリスト・スクリーナー・保有）を置かず、利用者のデータを書き換えない。
- 銘柄は 1 枚目の一覧から **ドラッグ＆ドロップ** で足す・入れ替える（今のフリー・グリッドと同じ操作）。キーでは銘柄ジャンプと C キー（FR-KB4）。
- 1 枚のモニタの利用者には何も増やさない。

### 1.1 第 2 版から変えたこと（なぜ疎結合になるか）

| 第 2 版                                                                       | 第 3 版                                                                                          | 効果                                                          |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| 子ウィンドウはどの種類のペインも置ける・今のタブを写せる                      | **フリー N だけ**（置けるのはチャート・マルチ時間軸・チャートグリッド・銘柄情報）                | 一覧が無いので、ウォッチリスト・保有の編集が 2 枚目で起きない |
| 利用者のデータを Core が正として全ウィンドウに配る（`user.changed` と `rev`） | 2 枚目は **読むだけ**。設定（テーマ・文字の大きさ・キー）と★の表示だけを受け取る                 | 一番大きかった「状態の同期の作り替え」が要らない              |
| リンク（同じ銘柄を追う）を main のバスでウィンドウをまたいで配る              | 2 枚目のペインは **リンク色なし（自分の銘柄を持つ）** が既定。ウィンドウをまたぐリンクは後の段階 | main のバスが最初の版では要らない                             |
| 子ウィンドウの種類（詳細・ウォール・タブの写し）                              | **フリー N の初期の形** として用意（§4.2）                                                       | 種類を増やさず、フリーの中で組み替えられる                    |

## 2. 今の構造で 1 ウィンドウ前提になっているところ

| 場所             | 今                                                                                                                              | 直すこと                                                                                                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| main             | `win`・`pageLoaded` が 1 つ。ダイアログの親・`app:setChrome`・`second-instance` が `win` 宛て。`minWidth: 1100`。新しい窓は拒否 | WindowManager に集め、IPC は送り元の窓（`BrowserWindow.fromWebContents(e.sender)`）を使う。フリー N は `minWidth` を小さく。窓を開くのは `fromApp` で確かめた専用の IPC から |
| main（位置）     | `window.json` は 1 件                                                                                                           | ディスプレイの組み合わせごとに各窓の位置を持つ（§5）                                                                                                                         |
| Core             | ポートは 1 本、`send()` は 1 つ                                                                                                 | 窓ごとのポート。返事は来たポートへ、イベントは全部へ                                                                                                                         |
| レイアウトの保存 | `LayoutDoc` を丸ごと保存                                                                                                        | フリー N は自分の分だけ保存する API を足す（1 枚目の保存とぶつからない）                                                                                                     |
| 一度きりの処理   | 初回起動・更新の確認・自動更新が `App.svelte` で窓ごとに動く                                                                    | 1 枚目だけが行う                                                                                                                                                             |

## 3. アーキテクチャ

### 3.1 ウィンドウ

- 1 枚目 = 今のアプリ（主ウィンドウ、`main`）。2 枚目以降 = **フリー 2・フリー 3・フリー 4**（固定のスロット `free2`〜`free4`。最大 3 枚。メモリのため）。
- フリー N も同じ renderer のバンドル。URL で自分のスロットを知る（`index.html?w=free2`）。フリー N のときは:
  - トップバーのタブ・ドロワー・ステータスバーのジョブ表示・初回起動・更新の確認を出さない（タイトル「フリー 2」とコマンドバーだけ）。
  - 置けるペインは **チャート・マルチ時間軸・チャートグリッド・銘柄情報**。ペインの種類の変更（Ctrl+Shift+N）もこの中から。
- 主ウィンドウを閉じるとアプリを終える（フリー N も閉じ、次の起動で開き直す）。フリー N を利用者が閉じたら、配置とレイアウトはスロットに残り、次に同じ番号を開けば元どおり。`parent` は付けない。

### 3.2 Core: 窓ごとのポート

- `ports: Map<slot, Port>`。要求には来たポートへ返事、イベント（データの更新・ジョブの進み・設定の変更）は全ポートへ。
- 読み込み直しで同じスロットから新しいポートが来たら、古いものを閉じて置き換える。「表示中の銘柄を先に取る」（FR-F8）はスロットごとに受けて和集合で使う。
- Core が落ちて立ち上げ直したら、main が全スロットに配線し直す。

### 3.3 同期は最小限（フリー N は読むだけ）

| 何を                                               | 向き                 | 方法                                                                                                                                                                                                             |
| -------------------------------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 市場データ（足・指標・配当）                       | Core → 全窓          | 今の `data.updated` を全ポートへ                                                                                                                                                                                 |
| 設定（テーマ・文字の大きさ・キー・移動平均の期間） | 1 枚目 → Core → 全窓 | 設定の保存のあと Core がイベント `settings.changed` を配る。フリー N は受けて置き換えるだけ（設定画面は 1 枚目で開く）                                                                                           |
| ★（お気に入り）の表示                              | 1 枚目 → Core → 全窓 | ウォッチリストの保存のあと Core が `watchlists.changed` を配る。フリー N は★の表示にだけ使う。**フリー N で★を押したときは** Core の `watchlist.toggleFav` を 1 つ足して Core が変え、全窓へ配る（後勝ちでよい） |
| レイアウト                                         | フリー N だけ        | `user.saveWindowLayout { slot, entry }`（自分の分だけ）。1 枚目の `LayoutDoc` には触らない                                                                                                                       |
| リンク・十字線                                     | —                    | 最初の版では同期しない（フリー N のペインはリンク色なしが既定）                                                                                                                                                  |

- 1 枚目の状態の持ち方（renderer が持ち、配列ごと保存）は **変えない**。フリー N は利用者のデータを書かない（★だけは Core の専用の操作で）。

### 3.4 レイアウトの保存: 今の形に足すだけ

```ts
interface LayoutDoc {
  version: 1
  active: PresetId // 1 枚目（今と同じ）
  entries: Record<PresetId, LayoutEntry> // 1 枚目（今と同じ。今のフリーもここ）
  links: Record<string, InstrumentId> // 1 枚目（今と同じ）
  windows?: Partial<Record<'free2' | 'free3' | 'free4', LayoutEntry>> // 足すだけ。タブもドロワーも持たない
}
```

- 今のフリー（1 枚目のタブ）とフリー N は **別のデータ**。フリー N の中身は 1 枚目の操作で変わらない。
- 古い版のアプリで開いても 1 枚目のレイアウトは消えない（`windows` を知らないだけ）。ペインの ID は全ウィンドウで重ならないよう `normalizeDoc` で確かめる。
- `windows` の書き込みは `user.saveWindowLayout` だけ。1 枚目の `user.saveLayout` は `windows` に触らない（Core が今の `windows` を残して 1 枚目の分だけ置き換える）。

## 4. フリー N でできること

### 4.1 操作

| 操作                         | マウス                                                                                                                                                                                                                                         | キー                                                                              |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 銘柄を足す・入れ替える       | 1 枚目のウォッチリスト・スクリーナー・ランキング・保有の行を、フリー N のチャートやグリッドのタイルに **ドラッグ＆ドロップ**（今のフリー・グリッドと同じ: タイルに落とせば入れ替え、グリッドの空きに落とせば足す、チャートに落とせばその銘柄） | 銘柄ジャンプ（数字を打つ）・C キー・コマンドバー（今と同じ。フリー N の中で完結） |
| 並べ方を組む                 | 見出しの分割・種類の変更、タイトルのドラッグ、画面の端への移動（今のフリーと同じ）                                                                                                                                                             | Ctrl+Shift+E / O / N、コマンドバー                                                |
| グリッドの格子・期間・時間軸 | ツールバー                                                                                                                                                                                                                                     | + − / Alt+1〜6 / D W M（今と同じ）                                                |

- ウィンドウをまたぐドラッグ: 1 枚目の行のドラッグはすでに `application/x-elecxstock-symbol`（銘柄 ID）と `text/plain`（コード）の両方を載せている。同じアプリの窓どうしなので届く見込みだが、**R1 の最初に試作して確かめる**（独自の形が届かなければ `text/plain` のコードで受ける）。

### 4.2 フリー N の初期の形（開くときに選ぶ。あとから自由に組み替えられる）

| 名前                         | 中身                                                | 想定                                                                       |
| ---------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------- |
| **チャートグリッド**（既定） | チャートグリッド 1 枚（このグリッドの銘柄、空から） | 1 枚目から銘柄をドラッグして並べる。今のグリッドと同じ格子・期間・並べ替え |
| **4 分割**                   | チャート 4 枚（2×2、それぞれ自分の銘柄）            | 大きめのチャートで見比べる                                                 |
| **詳細**                     | マルチ時間軸 + 銘柄情報                             | 1 銘柄を大きく（10 年分の配当の推移も）                                    |
| **空**                       | チャート 1 枚                                       | 自分で分割して組む                                                         |

### 4.3 キー

| 操作                                                         | キー                                                       |
| ------------------------------------------------------------ | ---------------------------------------------------------- |
| 新しいフリー N を開く（初期の形を選ぶ）                      | **Ctrl+Alt+N**                                             |
| 次・前のウィンドウへ（その窓で最後にフォーカスしたペインへ） | **Ctrl+F6 / Ctrl+Shift+F6**                                |
| ウィンドウを閉じる / 別のモニタへ / 全画面                   | Alt+F4 / Win+Shift+← → / F11（OS・今のまま。ヘルプに書く） |
| 閉じたフリー N を開き直す                                    | コマンドバー「フリー 2 を開く」など                        |
| 選んだ銘柄をフリー N へ送る                                  | **Ctrl+Alt+Enter**                                         |
| このウィンドウの文字を大きく / 小さく / 戻す                 | **Ctrl+Alt+= / Ctrl+Alt+- / Ctrl+Alt+0**                   |

## 5. 位置の記憶と戻し

- `window.json` を版 2 に: **ディスプレイの組み合わせ（全ディスプレイの位置・大きさ・倍率）ごと** に、各スロット（`main`・`free2`〜）の位置・最大化・全画面を持つ。ディスプレイの `id` や名前には頼らない（ドッキング・ドライバで変わる、同じ名前が多い）。
- 置き方は純粋な関数 `place(displays, saved) → bounds` にして単体で試す。記録の無い組み合わせではフリー N を主ディスプレイの見える位置へ寄せ、元の組み合わせの記録は上書きしない（戻れば元の位置に戻る）。
- 動作中に `display-removed` が来たら、その画面の窓は全画面を解いて主ディスプレイへ（この位置は記録しない）。倍率の違う画面へは「置く → 大きさ → 確かめる」の順。グリッドのタイルは `devicePixelRatio` が変わったら描き直す。

## 6. 段階

| 段階   | 中身                                                                                                                                                                                                                                                                                                                                                               |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **R1** | ウィンドウをまたぐドラッグの試作（最初に）。Core の窓ごとのポート。main の WindowManager（主 + フリー 2）・IPC の送り元化・1 枚目だけの処理。フリー N の画面（タブ・ドロワーなし、置けるペインの制限）。`user.saveWindowLayout`。`settings.changed`・`watchlists.changed` の配信と★の `watchlist.toggleFav`。初期の形の選択。Ctrl+Alt+N・Ctrl+F6。位置の記憶と戻し |
| R2     | フリー 3・フリー 4。ウィンドウごとの文字の大きさ。閉じたフリー N をコマンドバーから開き直す                                                                                                                                                                                                                                                                        |
| R3     | ウィンドウをまたぐリンク: main のバス（番号つき・最後の値を覚える）でリンク色 → 銘柄を配り、フリー N のペインにリンク色を付けると 1 枚目で選んだ銘柄を追う（こだまを防ぐ `applyRemoteLink`）                                                                                                                                                                       |
| R4     | キーだけでフリー N へ送る（FR-KB4。ウィンドウをまたぐドラッグの代わり）: 1 枚目の一覧で選んだ銘柄を「フリー N に送る」（Ctrl+Alt+Enter。Ctrl+Alt+→ は Windows の画面の回転と重なるため変えた）。送り先はフリー N でフォーカスしているペイン（グリッドなら足す、チャートなら入れ替え）。メモリの実測と記録                                                          |

## 7. テスト

- 単体: `place()`、`normalizeDoc`（`windows`・ペイン ID の重複）、`user.saveLayout` が `windows` を消さないこと、`watchlist.toggleFav`。
- E2E（Playwright `_electron`）: `app.waitForEvent('window')` でフリー 2 を取り、キーだけで開く・初期の形・銘柄ジャンプで足す・閉じて開き直す・再起動で戻る。**1 枚目の行をフリー 2 のタイルへドラッグして入れ替わる**こと（窓をまたぐドラッグは `dragTo` が使えないので、両窓の位置を main から取り `page.mouse` で行う。難しければ試作の結果で手動の確認に回す）。Ctrl+F6 は main の「いま前にある窓」の状態で確かめる。
- 固定データ: 版 1 の `window.json`、画面外の位置、`windows` を持つ `LayoutDoc` を古い版で開く。

## 8. リスク・未決

- **ウィンドウをまたぐドラッグ**が届くか（R1 の最初に試す）。届かない場合の代わり: 1 枚目の一覧で「フリー 2 に送る」（コマンドバー・キー。例 Ctrl+Alt+→）。
- メモリ: 実測は 1 枚目の renderer 約 190MB、フリー 2（グリッド）約 145MB（`docs/decisions.md`）。
- 終了: Core を止める前に、main が全窓へ保存（`app:flush`）を頼んで返事を待つ（実装済み）。
- フリー N で書けるのは★・◆とチャートの移動平均の期間（設定）だけ。ウォッチリストへの追加などは置かない。必要になったら Core の操作単位の API を足す。
