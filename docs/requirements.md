| #   | 判断                                                                                                 | 理由                                                                                                                 |
| --- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 1   | データ源は**プロバイダ抽象**の後ろに置き、既定は Node の `yahoo-finance2`                            | Python 製の yfinance は Electron に Python ランタイムの同梱が要る。`yahoo-finance2` は main 側の Node でそのまま動く |

| 7   | 利回りは**実績と予想を区別**し、算出式・基準日・出所を明示                                           | 「利回り」の定義で数値が大きく変わる                                                                                 |
| 8   | 銘柄コードは**英数字 4〜5 桁の文字列**、内部は不透明な ID（`JP:7203` など）                          | 2024年以降、`130A` のような英字入りコードがあり、優先株・社債型種類株式は 5 桁                                       |

| 10  | コードは**すべてオリジナル**、ライセンスは **MIT**                                                   | elecdex（GPL-3.0）のコードは MIT に持ち込めない。設計の考え方だけを参考にする                                        |

| 13  | **チャートグリッドで多数の銘柄を一括操作**し、一覧・スクリーナーは**自動で隠れるドロワー**に置く     | スクリーニング結果の値動きを並べて見比べ、売買の候補を絞る作業を 1 画面で行うため                                    |
| 14  | **GitHub Actions で CI/CD を P1 から回す**                                                           | 品質基準（§9.1）を人手に頼らず守り続けるため                                                                         |
| 15  | **スクリーニングの指標は登録表（`FieldDef`）で定義**し、画面・保存形式・計算をそこから導く           | 指標は使いながら増やし直すもの。保有に基づく指標（P3）も登録表に足すだけで使えるようにする                           |

## 1. プロジェクト概要

`elecxstock` は、日本株（東証）と J-REIT を中心に、**手元の PC にデータを蓄え、チャートを並べて見比べ、条件で銘柄を絞り込む**ためのデスクトップアプリである。

- **ローカルファースト**: データは利用者の PC の SQLite に置く。一度取り込めばオフラインでもチャートとスクリーニングが動く。
- **中長期分析に特化**: 日足・週足・月足が対象。ティック・分足・板・リアルタイム更新は扱わない（§1.2）。
- **プロ仕様の画面**: 機関投資家向け端末のように、情報密度が高く、キーボードで素早く操作できる業務画面。複数のチャートとリストを分割配置し、銘柄の選択を連動させる。
- **インカム重視**: 配当・分配金の履歴を持ち、利回りを第一級の指標として扱う。
- **UI と Core の分離**: Core（取得・保存・計算）は Electron に依存しないモジュールとし、UI は型付きの API 越しにだけ触れる。
- **日英 2 言語**: UI は日本語（既定）と英語。
- **公開前提**: MIT ライセンスで GitHub に公開する前提で、依存・同梱物・表記を選ぶ。

### 1.1 想定利用者と利用場面

- 個人投資家（まず作者本人）。高配当株・J-REIT の発掘と、監視銘柄のトレンド確認。
- 典型的な一日: 大引け後に更新 → お気に入り・監視リストを ↑↓ でめくりながら日/週/月足を確認 → スクリーナーで条件に合う銘柄を出し、**チャートグリッドに数十枚並べて時間軸・期間を一括で切り替えながら見比べ**、売買の候補に印を付ける → 候補をウォッチリストに入れる。
- マルチモニタ（2〜3 枚）での利用を想定する。

### 1.2 スコープ外（非目的）

- 分足・ティック・板・歩み値、リアルタイム株価
- 発注・口座連携
- 保有の記録（P2）と、保有に基づくスクリーニング（P3）は**初版（P1）では作らない**。後から入れられる設計にする（§6.9）
- 投資助言・売買シグナルの提示（アプリは計算結果を表示するのみ）
- 取得したデータの再配布・共有
- **海外市場の銘柄（米国株など）**。対象は東証の銘柄と日経平均だけにする（2026-11-14 に見送りを決定）。Yahoo は米国株も返すが、次の前提がすべて東証に合わせてあるため、足すには設計の作り直しが要る:
  - **銘柄の一覧**: JPX の上場銘柄一覧から取り込んでいる（§2）。海外の銘柄の一覧と、市場変更・上場廃止の差分の取り方が別に要る
  - **コードの形**: 銘柄ジャンプとコマンドバーの追加は、1〜9 で始まる 4〜5 桁の東証コードを前提にしている（FR-U5・§6.5）。英字だけのティッカー（`SPCX` など）は探せず、追加もできない
  - **日付と営業日**: 日付は日本時間、営業日は東証の暦で扱う（FR-T1・§3.4）。取引時間・休場日・夏時間の違う市場では、日足の日付、仮の足、取りこぼしの判定、自動更新の時刻がずれる
  - **通貨**: 価格・配当・時価総額・売買代金を円として計算・表示する（「億円」など）。ドル建てを混ぜると、スクリーナーの金額の条件・並べ替え・ヒートマップの大きさが比べられなくなり、為替の扱いも要る
  - **指標と配当**: 権利確定月・配当カレンダー・連続増配の数え方は、日本の配当の慣行（権利確定月・権利落ち日）に合わせて作り、東証の銘柄でしか確かめていない。四半期配当や源泉税の違う海外の銘柄では、別に検証が要る

## 3. データ取得

### 3.1 プロバイダ抽象

```ts
type JstDate = string // 'YYYY-MM-DD'（日本時間の日付。§3.4）
interface DataProvider {
  id: string // "yahoo" | "jquants" | ...
  priceBasis: 'split-adjusted' | 'unadjusted' // 日足と配当の金額の基準（Yahoo は split-adjusted、FR-D2）
  quoteBatchSize: number // 一括気配の 1 リクエストあたりの件数（既定 50、FR-F5）
  // 日足・月足と、その期間の配当・分割を 1 回で返す（Yahoo は 1 リクエスト）
  fetchHistory(
    id: InstrumentId,
    opt: { from: JstDate; interval: '1d' | '1mo'; signal: AbortSignal },
  ): Promise<{ bars: Bar[]; actions: Action[] }>
  fetchQuotes(ids: InstrumentId[], opt: { signal: AbortSignal }): Promise<Quote[]> // 当日の値と指標を一括
}
// エラーは「銘柄単位」（データなし・不正な応答）と「プロバイダ単位」（429・5xx・通信断）に分けて投げる（FR-F3）
```

| プロバイダ                        | 用途                               | 優先度     | 備考                                                                  |
| --------------------------------- | ---------------------------------- | ---------- | --------------------------------------------------------------------- |
| JPX 上場銘柄一覧（Excel）         | ユニバース・業種・市場区分・英語名 | P1         | 月次更新。認証不要                                                    |
| Yahoo Finance（`yahoo-finance2`） | 日足・配当・分割・一括気配・指標   | P1（既定） | 非公式 API。仕様変更・取得不能を前提に設計する（NFR-R3）              |

| EDINET API（金融庁）              | 有報ベースの財務                   | P3         | API キー要                                                            |
| 手入力・CSV 取り込み              | 欠けた値の補完                     | P3         |                                                                       |

### 3.2 取得ジョブとレート制御

| ID     | 要求                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | 優先度 |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| FR-F1  | 取得は**永続化されたジョブキュー**で行う。アプリを終了しても次回起動時に未完了から再開する。終了するときは Core に止めるよう頼み、実行中の項目を止めてジョブを「待ち」に戻し、DB を閉じてから終わる（応答が無ければ 6 秒で強制終了。項目の書き込みはトランザクションなので半端な状態は残らない）。分割を見つけたときの月次系列の取り直しは日足と同じトランザクションで記録し、閉じても次の日々の更新で取り直す                                                                                                                                        | P1     |
| FR-F10 | **更新済みの知らせ**: 更新（F5）を押したとき、取得中なら「更新中」、最新なら「データは最新です」と知らせる（「それでも更新」で取り直せる）。最新とするのは、取得の対象のすべての銘柄に日足があり（新しく足した行・取得に失敗した銘柄が無い）、最後の更新が直近の取引日の大引けと、直近の海外の終値の区切り（火〜土の朝 7:00。米国の大引けは日本時間の 5〜6 時）のどちらよりも後のとき（`src/shared/freshness.ts`）。何も起きないように見せない                                                                                                        | P2     |
| FR-F2  | プロバイダごとに**最小リクエスト間隔（Yahoo は 1.0 秒 + 0〜0.3 秒の揺らぎ）**を空け、**1 件ずつ順に**取る（同時には送らない）。間隔はプロバイダのコードで決め、利用者の設定にはしない（送りすぎて止められないため）                                                                                                                                                                                                                                                                                                                                   | P1     |
| FR-F3  | 失敗は「銘柄単位」（データなし・不正な応答）と「プロバイダ単位」（429・5xx・タイムアウト）に分ける。プロバイダ単位は指数バックオフで再試行し、連続失敗が閾値を超えたらそのプロバイダを一時停止して知らせる。銘柄単位の失敗は停止の判定に数えない。通信断（オフライン）を検知したら、失敗として数えずに復帰を待つ                                                                                                                                                                                                                                      | P1     |
| FR-F4  | 進捗（件数・完了・失敗・残り時間の見積もり）を UI に配信し、一時停止・取り消しができる                                                                                                                                                                                                                                                                                                                                                                                                                                                                | P1     |
| FR-F5  | 指標（PER・PBR・時価総額・発行済株式数・BPS・EPS）と当日の値は**一括気配（`quote`）**で取る。1 リクエストの件数は設定値（既定 50。上限は P1 前半に実測、§13）。銘柄ごとの `quoteSummary` は使わない                                                                                                                                                                                                                                                                                                                                                   | P1     |
| FR-F6  | 起動時と起動中に、最後の更新が直近の大引け（日本時間 15:30。東証の営業日に限る）より前なら自動で更新する（既定は大引けの 30 分後から。設定で切れる）                                                                                                                                                                                                                                                                                                                                                                                                  | P2     |
| FR-F7  | 取得失敗の銘柄と理由を記録し、jobs ペインで見られる                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | P1     |
| FR-F8  | 取得中でも、取得済みの銘柄からチャートとスクリーニングを使える。ジョブは「表示中の銘柄 > お気に入り・ウォッチリスト・保有 > その他」の順に処理し、表示中の銘柄が変われば順番を入れ替える。日々の更新でも同じで、一括気配は指数・ウォッチリスト・保有の銘柄のバッチから取り、その銘柄の日足の取り直しは次のバッチより先に行う                                                                                                                                                                                                                          | P1     |
| FR-F9  | **日々の更新方式**: 全銘柄の当日の値は一括気配で取り、当日の足を作る（FR-D8）。銘柄ごとの日足の取得（`fetchHistory`）は次の銘柄に限る: (a) 気配の前日終値と保存済みの終値が食い違う（分割・併合の疑い）、(b) 2 営業日以上取りこぼしている、(c) 毎日ユニバースの 1/20 ずつ回す定期照合（各銘柄がおよそ月 1 回照合され、遅れて載った配当も拾う）。ジョブの最後に 1 回だけ取りこぼしを確かめ、そのジョブで気配を取れなかった銘柄（バッチの失敗・応答に無い）は気配を、日足が欠けたままの銘柄は日足を取り直す（確認は繰り返さない。初回の取り込みも同じ） | P1     |

参考見積もり（P0 の実測から）: 日足は 1 銘柄 1 リクエスト（170〜430ms）で全期間・配当・分割が取れる。約 2,000 銘柄の**初回取得**は 1 秒間隔で約 35〜40 分。**日々の更新**（FR-F9）は一括気配 約 40 リクエスト + 照合 約 100 銘柄で **5 分以内**（NFR-P6）。

### 3.3 差分更新と補正

| ID    | 要求                                                                                                                                                                                                                                                                                                                                                                                                  | 優先度  |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| FR-D1 | 銘柄ごとに最終取得日を持ち、日足を取るときは `最終取得日 − 10 暦日` から取り直して upsert する（遡及訂正への追従。暦日で数えるので休場日の表に依存しない）                                                                                                                                                                                                                                            | P1      |
| FR-D2 | Yahoo の日足は**分割調整済み**で返る（未調整の値は返らない）。保存は「分割調整済みの OHLCV」と「分割・併合・配当のイベント」に分ける。**配当込みの調整値（`adjclose`）は保存しない**（配当落ちのたびに過去の全期間が変わり、重ね取りでは整合しないため）。未調整の価格は分割係数で戻し、配当込みの価格は保存済みの配当から Core で計算する                                                            | P1      |
| FR-D3 | 分割・併合は「新しい分割イベント」または「重ね取り区間で、保存済みの終値と取り直した値が食い違う」ことで検知する。検知した銘柄は全期間を取り直し、**取得に成功してから**日足・月次系列・配当・`metrics` を 1 トランザクションで置き換える（FR-S11）。併合・端数比率（例 1:1.1）の扱いは P1 前半に実データで確かめ、単体テストにする（§13）                                                            | P1      |

- FR-I1（P1）: 利回りの列には「実績」か「予想」か・基準日・出所を必ず併記する。片方だけを「利回り」と呼ばない。
- FR-I2（P1）: 利回りの分子（過去12か月の配当合計）と分母（終値）は同じ株数の基準に揃える。Yahoo は配当の金額も分割調整済みで返す（P0 で確認）ので、保存値どうしで割れば揃う。プロバイダの `priceBasis` が未調整なら、分割係数で揃えてから合計する。**評価日を固定したフィクスチャ（例: 9434 の 10:1 分割の直後の日付）で基準が一致することを、Core の最初の単体テストにする**。記念・特別配当も配当として合計する。
- FR-I3（P2）: J-REIT の決算期変更で 12 か月に分配が 1 回・3 回入る場合に備え、「直近の決算期 2 回分を年換算」する方式も選べるようにする。P0 では 8 銘柄の分配金履歴が 2010 年以降 6 か月ごとに欠けなく並ぶことを確認した（不規則は合併直後の 1 件のみ）。
- FR-I4（P1）: 利回りは Yahoo の利回り系の値（`trailingAnnualDividendRate` など）を使わず、必ずローカルの配当履歴から計算する（P0 で、履歴があるのに 0 を返す銘柄を確認した）。
- FR-I5（P3）: J-REIT は物件売却益などで分配金が一時的に増え、翌期に「減配」と判定されやすい。連続増配・非減配年数に、一時的な増減をならす方式を足すかは、使いながら決める。
- FR-I6（P3）: 銘柄情報のペインは、上から値段の欄（値段・前日比・52 週の高値と安値とその日・移動平均からの乖離・当日の始値・高値・安値・前日終値・出来高・保有の帯）、主な数字（実績利回り・PER（REIT は直近 2 期の年換算利回り）・PBR・時価総額・売買代金・最低投資金額）、予定、配当、値動き・保有・アラートの順に並べる。枠の幅で並びを変える（700px 未満は 1 列、700〜1039px は右に配当、1040px 以上は 1 段目に値段と主な数字）。値の無い行は出さない。デザインは docs/mock/info.html。
- FR-I7（P3）: 実績利回り・PER・PBR は、同じ業種（J-REIT はまとめて 1 つ）の中央値との差を添える（5 銘柄未満の業種は出さない）。配当込みの騰落率（1・3・5 年）・最大下落率（5 年、配当込み）・実績利回りの 5 年の範囲を出す。配当込みはチャートの「配当込み」と同じ考え方で計算する。これらは表示中の銘柄だけ Core がその場で計算する（全銘柄の指標には入れない。decisions.md）。
- FR-I8（P3）: 次の権利付最終日（権利確定日を月末として 2 営業日前。休場日なら前の営業日から数える）と権利落ち日を「目安」として出す。5 年の増配率（年率）を出す。連続増配の年数が配当の記録の長さで頭打ちのときは「以上」と書く。
- FR-I9（P3）: 次の決算発表の日を、Yahoo の一括気配（`earningsTimestampStart`。過去なら出さない）から出す。Yahoo の推定（`isEarningsDateEstimate`）のときは「推定」と書く。前回の決算発表（`earningsTimestamp`）も持つ。
- 売買代金（20 日平均）は、流動性の低い小型株・REIT を除くための重要な条件として、スクリーナーの既定の列と高配当プリセットに入れる。

  - 金額の値は表示の単位で打つ・出す（1 株あたりは円、最低投資金額は万円、時価総額・売買代金は億円。「30万」「1.5億」のように単位を付けてもよい。アラートの条件も同じ）

### 5.3 指標の登録表（あとから足し・直しやすい構造）

スクリーニングの項目は使いながら増やす・直すものなので、**指標を 1 か所の登録表で定義し、画面・保存形式・計算はそこから導く**。P1 からこの構造で実装し、保有に基づく指標（P3）も同じ方法で足す。

```ts
interface FieldDef {
  id: string // 'yield.trailing' | 'ret.1y' | 'holding.pnlPct' ...（保存した条件はこの ID で参照する）
  version: number // 定義（計算式・単位）を変えたら上げる。保存した条件の移行に使う
  label: { ja: string; en: string }
  description?: { ja: string; en: string } // 算出式・基準日・出所（FR-I1）をここに書き、画面のヒントに出す
  category: 'price' | 'value' | 'income' | 'technical' | 'return' | 'user' | 'holding'
  type: 'number' | 'percent' | 'money' | 'bool' | 'enum' | 'date'
  unit?: 'yen' | 'pct' | 'x' | 'days' | 'shares'
  source: // どこから値を得るか
    | { kind: 'metrics'; column: string } // FR-S10 の metrics 表の列（市場データだけで決まる指標）
    | { kind: 'compute'; fn: (ctx: FieldContext) => number | null } // 実行時に計算（利用者のデータを使う指標など）
  requires?: Array<'daily' | 'dividends' | 'fundamentals' | 'holdings'> // 足りなければ欠損（FR-D9）、holdings が無ければ項目ごと出さない
  operators: Array<'>=' | '<=' | '=' | '!=' | 'between' | 'in'>
  defaultFormat: { digits: number }
  availableFrom: 'P1' | 'P2' | 'P3'
}
```

| ID     | 要求                                                                                                                                                                                                                                              | 優先度 |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| FR-FD1 | 指標はすべて `FieldDef` の登録表で定義する。スクリーナーの条件エディタ・結果表の列・一覧の列・chart-grid の並べ替え・コマンドバーの指標検索は、登録表を読んで作る（画面ごとに指標を書かない）                                                     | P1     |
| FR-FD2 | 指標の追加は「登録表に 1 項目を足す（市場データだけで決まるなら `metrics` に列を足す移行も 1 つ）＋単体テスト」で終わること。画面のコードは変えない                                                                                               | P1     |
| FR-FD3 | 市場データだけで決まる指標は `metrics` 表に保存して速く引く（FR-S10）。利用者のデータ（お気に入り・ウォッチリスト・保有）を使う指標は保存せず、実行時に計算する（利用者のデータを変えてもすぐ反映され、市場データの DB を取り直しても失われない） | P1     |
| FR-FD4 | 登録表の整合を単体テストで確かめる: ID の重複が無い、日英の表示名がある、型と演算子が合う、`metrics` 由来の列が実在する                                                                                                                           | P1     |

### 6.2 銘柄リンクグループ

- FR-K1（P1）: 同じ色のペインは「選択中の銘柄」を共有する。
- FR-K2（P1）: リストで ↑↓ を押すと同色のチャートが即座に切り替わる（**チャートめくり**、100ms 以内）。
- FR-K3（P2）: 同色のチャート間で十字線を同期する。時間軸が違うときは、その日付を含む足（日→週→月）に合わせる。
- FR-K4（P2）: 同色・同時間軸のチャート間で表示期間を同期するかをペインごとに選ぶ。

### 6.5 キーボード操作（マウスなしで完結する）

### 6.14 アラート（P3）

手元のデータを更新したときに、利用者が決めた条件が成り立ったかを判定して知らせる。設計は [design-alerts.md](design-alerts.md)、画面のモックは [mock/alerts.html](mock/alerts.html)。

## 7. チャート

### 7.1 描画

- **ライブラリ**: TradingView **Lightweight Charts**（Apache-2.0、2D Canvas）。Series Primitives で一目の雲・配当落ちの印などを自前描画する。帰属表示（ロゴかリンク）が必要（§10）。
- **WebGL は使わない**（チャートを多く並べたときに、Chromium の WebGL コンテキスト上限 約 16 に当たらないため）。
- 見えていないペインは描画を止める。
- chart-grid（最大 30 枚）は、Lightweight Charts のインスタンスを並べるか、1 枚の Canvas に自前で描くかを、NFR-P7（30 枚を 300ms 以内）を満たす方で選ぶ（P1 前半に計測）。

## 8. アーキテクチャ

### 8.1 プロセス構成

```
┌ renderer（UI: Svelte 5） ─────────────────────────────┐
│ Layout ─ PaneHost ─ WidgetRegistry                   │
```

### 9.1 商用プロダクト品質の基準

「個人の道具」ではなく、市販の業務ソフトと並べて遜色のない仕上がりを求める。

| ID      | 要求                                                                                                                                                                                                                                                                           |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| NFR-Q1  | **一貫性**: 色・文字・余白・角・線の太さはデザイントークンだけから取り、ペインごとの独自の値を書かない。トークンは `src/renderer/app.css` の CSS 変数に置く                                                                                                                    |
| NFR-Q2  | **状態の網羅**: すべてのペイン・ダイアログ・入力に、通常・フォーカス・無効・読み込み中・空・エラーの見た目を定義する（FR-V11）                                                                                                                                                 |
| NFR-Q3  | **ちらつき・ずれがない**: データの読み込みや更新でレイアウトが動かない（領域を先に確保する）。数値の桁が変わっても列幅が揺れない                                                                                                                                               |
| NFR-Q4  | **表示倍率**: Windows の表示スケール 100〜200%、倍率の違うモニタ間でウィンドウを動かしても、線・文字・チャートがにじまない（Canvas は devicePixelRatio に追従）                                                                                                                |
| NFR-Q5  | **アクセシビリティ**: 文字と背景のコントラストは WCAG 2.2 AA 以上。上昇・下落は色だけでなく符号（+ / −）でも示す。主要な要素にアクセシブルな名前を付ける                                                                                                                       |
| NFR-Q6  | **文言**: 日英とも同じものは同じ言葉で呼ぶ（文言は `src/renderer/lib/i18n.ts` の `ja` / `en` に置き、キーの一致は単体テストで確かめる）。エラーには「何が起きたか・どうすればよいか」を書く                                                                                    |
| NFR-Q7  | **応答**: 操作に 100ms 以内で反応し、1 秒を超える処理は進捗を出し、取り消せる                                                                                                                                                                                                  |
| NFR-Q8  | **ウィンドウ**: 位置・大きさ・最大化・モニタを記憶し、モニタが外れたら見える位置に戻す。最小サイズを決め、それ以下でも崩れない                                                                                                                                                 |
| NFR-Q9  | **配布**: インストーラ（NSIS）、アンインストール時に利用者データを残すか尋ねる（P1）。コード署名はしない前提とし、**自動アップデートは行わず「新しいバージョンがあります」の通知だけ**にする（GitHub Releases を見る。P2）。署名を入れる場合は改めて自動アップデートを検討する |
| NFR-Q10 | **見た目の回帰テスト**: ダイアログ（初回の確認・ショートカット一覧・設定）のスクリーンショットを基準画像と比べ、意図しない変化を検出する（§11。P2。データを描く画面は基準画像が安定しないため対象外）                                                                          |
| NFR-Q11 | **クラッシュ**: renderer・utilityProcess が落ちても自動で立ち上げ直し、利用者のデータとレイアウトを失わない。原因はローカルのログに残す（外部送信はしない）                                                                                                                    |

## 11. テスト方針

テストの作り（層・置き場所・共通の部品・きまり）は [testing.md](testing.md)、作り直しの計画と経緯は [test-plan.md](test-plan.md)。

- **単体（Vitest。L1・L2）**: 調整係数・週月集計・指標・利回り（評価日を固定したフィクスチャ。FR-I2）・営業日の判定・スクリーナーの条件評価・
  条件の値の表示と入力・アラートの判定・保有の計算・レイアウト操作・レート制御と失敗の分類。登録表（指標・アクション・利用者のデータを書くメソッド・
  文言）は「すべての項目について」確かめ、指標の性質の表はスナップショットで持つ（FR-FD4, FR-N6）。同じ値を出す 2 つの経路は突き合わせる。
- **結合（Vitest。L3・L4）**: Core + SQLite（初回取得の済んだ種の DB の写し）で、日々の更新 → 分割・併合の検知 → 取り直し（取得失敗時に既存データが
  残ること、FR-S11）、保存期間、全データの削除、DB と利用者のデータの移行、利用者のデータの書き出しと取り込み（FR-S12）。画面のロジック（一覧の列・
  保有の評価）は、製品と同じ経路（検証・構造化複製）で Core につないで確かめる。
- **E2E（Playwright `_electron`）**: プロバイダはローカルスタブ、時刻は `ELECXSTOCK_NOW` で固定。**マウスを使わない操作だけで一日の流れを通すシナリオ**（§6.5）、
  状態の変化への追従、重なり（押せない要素が無いこと）、言語の切り替え、複数の窓、時間の経過。
- **見た目の回帰**: ダイアログの日英・ダーク/ライト（NFR-Q10）。
- **性能**: NFR-P2, P3 を種の DB と固定のダミーデータで計測する。
- **契約テスト**: 実際の Yahoo・JPX に対する夜間のスモークテスト（NFR-CI3）。
- **漏れの検出**: 要求の ID とテストの突き合わせ（`npm run trace`）と、フォルダごとのカバレッジの下限（`npm run coverage`）。
- すべて GitHub Actions で自動実行する（§9.2）。
