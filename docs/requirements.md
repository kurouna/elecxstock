## 0. 主な設計判断

| # | 判断 | 理由 |
|---|---|---|
| 1 | データ源は**プロバイダ抽象**の後ろに置き、既定は Node の `yahoo-finance2` | Python 製の yfinance は Electron に Python ランタイムの同梱が要る。`yahoo-finance2` は main 側の Node でそのまま動く |
| 2 | 取得は**レート制御付きの永続ジョブキュー**（最小間隔・同時数・指数バックオフ・中断と再開・進捗通知） | 固定バッチ + Sleep では 429 に追従できず、途中で落ちると最初からやり直しになる |
| 3 | 差分更新は**数日の重ね取り + 分割の検知で銘柄単位の再取得** | 分割・併合で過去の調整後価格が全部変わる |
| 4 | **日足だけを取得し、週足・月足はローカルで集計**（長期の月足のみ別系列、P0 で確認） | 取得回数が減り、時間軸どうしが必ず整合する |
| 5 | **Main は薄く、Core は Electron 非依存で utilityProcess に置く** | 同期 SQLite と計算を main で回すとウィンドウ操作ごと固まる。Core はそのまま CLI に使える |
| 6 | **木構造のペインレイアウト + 銘柄リンクグループ + 保存レイアウト** | トレーダーの画面を作るには固定の 3 分割では足りない |
| 7 | 利回りは**実績と予想を区別**し、算出式・基準日・出所を明示 | 「利回り」の定義で数値が大きく変わる |
| 8 | 銘柄コードは**英数字4桁の文字列** | 2024年以降、`130A` のような英字入りコードがある |
| 9 | **キーボードだけで全操作**でき、**商用プロダクト品質**を基準にする | プロ向けの業務画面としての使い勝手と仕上がりを優先する |
| 10 | コードは**すべてオリジナル**、ライセンスは **MIT** | elecdex（GPL-3.0）のコードは MIT に持ち込めない。設計の考え方だけを参考にする |

## 1. プロジェクト概要

`elecxstock` は、日本株（東証）と J-REIT を中心に、**手元の PC にデータを蓄え、チャートを並べて見比べ、条件で銘柄を絞り込む**ためのデスクトップアプリである。

- **ローカルファースト**: データは利用者の PC の SQLite に置く。一度取り込めばオフラインでもチャートとスクリーニングが動く。
- **中長期分析に特化**: 日足・週足・月足が対象。ティック・分足・板・リアルタイム更新は扱わない（§1.2）。
- **プロ仕様の画面**: 機関投資家向け端末のように、情報密度が高く、キーボードで素早く操作できる業務画面。複数のチャートとリストを分割配置し、銘柄の選択を連動させる。
- **インカム重視**: 配当・分配金の履歴を持ち、利回りを第一級の指標として扱う。
- **UI と Core の分離**: Core（取得・保存・計算）は Electron に依存しないモジュールとし、UI は型付きの API 越しにだけ触れる。
- **日英 2 言語**: UI は日本語（既定）と英語。
- **公開前提**: MIT ライセンスで GitHub に公開する前提で、依存・同梱物・表記を選ぶ。

### 1.1 想定利用者と利用場面

- 個人投資家（まず作者本人）。高配当株・J-REIT の発掘と、監視銘柄のトレンド確認。
- 典型的な一日: 大引け後に更新 → お気に入り・監視リストを ↑↓ でめくりながら日/週/月足を確認 → スクリーナーで条件に合う銘柄を出し、ミニチャートの一覧で眺める → 気になる銘柄をお気に入りに入れる。
- マルチモニタ（2〜3 枚）での利用を想定する。

### 1.2 スコープ外（非目的）

- 分足・ティック・板・歩み値、リアルタイム株価
- 発注・口座連携
- 保有の記録と損益（**初版では作らない**が、後から足せる設計にする。§6.9）
- 投資助言・売買シグナルの提示（アプリは計算結果を表示するのみ）
- 取得したデータの再配布・共有

## 3. データ取得

### 3.1 プロバイダ抽象

```ts
interface DataProvider {
  id: string                                    // "yahoo" | "jquants" | ...
  capabilities: Set<'daily' | 'monthly' | 'quote' | 'dividends' | 'splits' | 'fundamentals' | 'forecast'>
  fetchDaily(code: string, from: Date): Promise<DailyBar[]>          // 未調整 OHLCV
  fetchCorporateActions(code: string, from: Date): Promise<Action[]> // 配当・分割
  fetchQuotes(codes: string[]): Promise<Quote[]>                     // 複数銘柄を一括
  fetchFundamentals?(code: string): Promise<Fundamentals>
}
```

| プロバイダ | 用途 | 優先度 | 備考 |
|---|---|---|---|
| JPX 上場銘柄一覧（Excel） | ユニバース・業種・市場区分・英語名 | P1 | 月次更新。認証不要 |
| Yahoo Finance（`yahoo-finance2`） | 日足・配当・分割・一括気配・指標 | P1（既定） | 非公式 API。仕様変更・取得不能を前提に設計する（NFR-R3） |
| J-Quants API（JPX 公式） | 日足・財務・予想配当 | P3 | 利用者が API キーを設定した場合のみ |
| EDINET API（金融庁） | 有報ベースの財務 | P3 | API キー要 |
| 手入力・CSV 取り込み | 欠けた値の補完 | P3 | |

### 3.2 取得ジョブとレート制御

| ID | 要求 | 優先度 |
|---|---|---|
| FR-F1 | 取得は**永続化されたジョブキュー**で行う。アプリを閉じても次回起動時に未完了から再開する | P1 |
| FR-F2 | プロバイダごとに**最小リクエスト間隔（既定 1.0 秒 + 揺らぎ）・同時実行数（既定 1）**を設定できる | P1 |
| FR-F3 | 429 / 5xx / タイムアウトは指数バックオフで再試行し、連続失敗が閾値を超えたらそのプロバイダを一時停止して知らせる | P1 |
| FR-F4 | 進捗（件数・完了・失敗・残り時間の見積もり）を UI に配信し、一時停止・取り消しができる | P1 |
| FR-F5 | 一括で取れる API（複数銘柄の気配）は一括で使う | P2 |
| FR-F6 | 大引け後（既定 16:00 以降）に起動中なら自動更新する。東証の休場日は更新しない | P2 |
| FR-F7 | 取得失敗の銘柄と理由を記録し、jobs ペインで見られる | P1 |
| FR-F8 | 初回取得中でも、取得済みの銘柄からチャートとスクリーニングを使える | P1 |

参考見積もり: 約2,000銘柄の初回取得（日足 5 年 + 配当・分割）は、1銘柄1〜2リクエスト・1秒間隔で **約35〜70分**（期間を延ばしてもリクエスト数はほぼ変わらない）。

### 3.3 差分更新と補正

| ID | 要求 | 優先度 |
|---|---|---|
| FR-D1 | 銘柄ごとに最終取得日を持ち、`最終取得日 − 重ね取り（既定 5 営業日）` から取り直して upsert する | P1 |
| FR-D2 | 価格は**未調整の OHLCV と、分割・併合・配当のイベント**を分けて保存し、調整後価格は表示時に係数で計算する | P1 |
| FR-D3 | 新しい分割・併合を検知した銘柄は履歴を取り直して整合を確かめる | P1 |
| FR-D4 | 週足・月足は日足から集計する（週は月曜始まり、祝日で欠けた週も 1 本） | P1 |
| FR-D5 | 異常値（高値 < 安値、終値 0、前日比 ±50% 超で分割イベントなし等）を検知して印を付ける | P2 |
| FR-D6 | 日足の保存期間は**既定 5 年、1〜10 年を年単位**で設定する。延ばしたときは不足分を取り足すジョブを積む。縮めたときは、消える期間・件数・おおよその容量を示して確認し、承諾されたら範囲外の日足を **DB から削除**する（取り消せば設定を元に戻す）。削除後は空き領域を回収する（`VACUUM` をジョブとして実行） | P1 |
| FR-D7 | 月足の長期表示用に、Yahoo の月次系列（`interval=1mo`）を最長期間で別に持つ（既定 5 年では月足が 60 本しかなく、60 か月移動平均が描けないため）。**P0 で、取れる期間と、日足から集計した月足との一致を確かめてから採用する**。取れない・合わない場合は月足も日足からの集計だけにする。保存期間の範囲内は日足からの集計を使い、それより前を月次系列で補う。保存期間の短縮（FR-D6）では消さない | P2（P0 で確認） |

## 4. データ保存

| ID | 要求 | 優先度 |
|---|---|---|
| FR-S1 | SQLite 1 ファイル（userData 配下）、WAL モード | P1 |
| FR-S2 | スキーマにバージョンを持ち、起動時にマイグレーションする | P1 |
| FR-S3 | DB のバックアップと、銘柄・期間を指定した CSV 書き出し | P2 |
| FR-S4 | **利用者のデータ**（お気に入り・ウォッチリスト・保存スクリーン・レイアウト・設定）は市場データの DB と分け、JSON（zod で検証）に置く。市場データの DB は消しても取り直せるが、利用者のデータは消えないこと | P1 |
| FR-S5 | 設定画面の「データ」に、市場データの状態（DB の容量・銘柄数・期間・最終更新・取得失敗の件数）を出す | P1 |
| FR-S6 | **全データの削除と取り直し**: 取得済みの市場データ（日足・月次系列・配当・分割・指標・取得状態）をすべて消し、初回と同じ取得ジョブを積む。ユニバース（銘柄一覧）も取り直す。**利用者のデータ（FR-S4）は消さない** | P1 |
| FR-S7 | **銘柄を指定した削除と取り直し**: 1 銘柄または複数銘柄（ウォッチリスト単位も可）のデータだけを消して取り直す。symbol-info とコマンドバーからも実行できる | P1 |
| FR-S8 | 削除の前に、消える内容・件数・容量と、取り直しにかかる時間の見積もりを示して確認する。実行中の取得ジョブがあれば先に止める。削除後は空き領域を回収する（`VACUUM`） | P1 |
| FR-S9 | 取り直しの途中でアプリを閉じても、次回起動時に続きから取り直す（FR-F1）。取り直しが終わるまで、未取得の銘柄はチャートとスクリーナーで「未取得」と分かるように出す | P1 |

主な表（案）: `instruments`、`daily_bars`、`monthly_bars`（FR-D7 を採る場合）、`corporate_actions`、`fundamentals_snapshot`、`fetch_state`、`jobs`、`fetch_log`。

利用者のデータは銘柄ごとの入れ物を持ち、お気に入りも保有もここにぶら下げる（§6.9）:

```ts
interface UserInstrumentData {
  favorite?: { since: string }        // P1
  tags?: string[]                     // P3
  note?: string                       // P3
  holdings?: Lot[]                    // 予約（P3 以降）。初版では読み書きしない
}
```

SQLite のライブラリは `better-sqlite3` と Node 組み込みの `node:sqlite` を P0 で比較して決める。後者は再ビルドが要らず、Electron と CLI で同じものが動く。

## 5. 指標とスクリーニング

### 5.1 指標

| 区分 | 指標 | 計算元 | 優先度 |
|---|---|---|---|
| 価格 | 終値、前日比、52週高値・安値と乖離、売買代金（20日平均） | ローカル日足 | P1 |
| 規模 | 時価総額 | 終値 × 発行済株式数 | P1 |
| バリュー | PER、PBR | プロバイダ値 or 計算 | P1 |
| **インカム** | **実績配当利回り / 実績分配金利回り** | 過去12か月の権利落ち日ベースの配当合計 ÷ 終値 | **P1** |
| インカム | 予想配当利回り（参考） | `yahoo-finance2` の予想年間配当（`summaryDetail.dividendRate` 等）÷ 終値。**P0 で日本株・J-REIT の値の有無と正しさを確かめ、使えなければ載せない** | P2（条件付き） |
| インカム | 配当性向、連続増配・非減配年数、権利確定月 | 配当履歴・財務（増配年数は保存期間の範囲内で数える） | P2 |
| テクニカル | 移動平均乖離率、ゴールデン/デッドクロス発生日、RSI、出来高急増 | ローカル日足 | P2 |
| リターン | 1か月・3か月・1年・3年の騰落率 | ローカル日足 | P2 |
| 利用者 | **お気に入りか** | 利用者のデータ | **P1** |

- FR-I1（P1）: 利回りの列には「実績」か「予想」か・基準日・出所を必ず併記する。片方だけを「利回り」と呼ばない。
- FR-I2（P1）: 分割を挟む配当は分割係数で揃えてから合計する。
- FR-I3（P2）: J-REIT の決算期変更で 12 か月に分配が 1 回・3 回入る場合に備え、「直近の決算期 2 回分を年換算」する方式も選べる。
- 指標は `FieldDef`（id・型・単位・表示名 ja/en・計算関数）の登録表で持ち、後から保有に関する指標（取得単価利回りなど）を足せるようにする。

## 6. 画面とレイアウト（ペイン）

elecdex・elecxterm のペインの考え方を引き継ぐ。**チャートもリストもスクリーナーも、同じ「ペイン」として木構造のレイアウトに置く**。

### 6.1 レイアウトモデル

```ts
type LayoutNode = SplitNode | TabsNode | PaneNode
interface SplitNode { kind: 'split'; id: string; direction: 'row' | 'column'; children: LayoutNode[]; sizes: number[] }
interface TabsNode  { kind: 'tabs';  id: string; children: PaneNode[]; activeIndex: number }
interface PaneNode  { kind: 'pane';  id: string; widget: WidgetId; link?: LinkGroup; props?: Json; state?: Json }
type LinkGroup = 'red' | 'green' | 'blue' | 'yellow' | 'purple'
```

| ID | 要求 | 優先度 |
|---|---|---|
| FR-L1 | ペインの分割（左右・上下）、閉じる、区切り線のドラッグとダブルクリックでの等分 | P1 |
| FR-L2 | タイトルのドラッグでペインを移動・タブ化 | P2 |
| FR-L3 | 1 ペインの最大化と戻す | P1 |
| FR-L4 | レイアウトに名前を付けて保存・切り替え。作業に追従して自動保存（スナップショットではない） | P2 |
| FR-L5 | プリセットを同梱（§6.4）。選ぶと保存レイアウトが 1 つ増える | P1 |
| FR-L6 | レイアウトの変更は純粋関数（layout-ops）で行い、ディスクから読んだ木は正規化してから使う | P1 |
| FR-L7 | ペインを別ウィンドウに切り出す（マルチモニタ）。ウィンドウごとにレイアウトと位置を復元 | P3 |
| FR-L8 | ペイン 1 つの例外はそのペインだけを止め、再試行とエラー通知を出す | P1 |

### 6.2 銘柄リンクグループ

- FR-K1（P1）: 同じ色のペインは「選択中の銘柄」を共有する。
- FR-K2（P1）: リストで ↑↓ を押すと同色のチャートが即座に切り替わる（**チャートめくり**、100ms 以内）。
- FR-K3（P2）: 同色のチャート間で十字線を同期する。時間軸が違うときは、その日付を含む足（日→週→月）に合わせる。
- FR-K4（P2）: 同色・同時間軸のチャート間で表示期間を同期するかをペインごとに選ぶ。

### 6.5 キーボード操作（マウスなしで完結する）

プロの利用者は手をキーボードから離さない。**基本的な操作はすべてキーボードだけでできる**ことを要求とし、マウスは補助とする。

#### 6.5.1 原則

| ID | 要求 | 優先度 |
|---|---|---|
| FR-KB1 | アプリのすべての操作は「アクション」として登録表に定義し、メニュー・ボタン・ショートカット・コマンドバーは同じアクションを呼ぶ。**キーの割り当てが無いアクションも、コマンドバーから必ず実行できる** | P1 |
| FR-KB2 | ペイン間・ペイン内のフォーカス移動、一覧の行・列の移動、ダイアログ・メニュー・条件エディタ・設定画面の操作がすべてキーで行える | P1 |
| FR-KB3 | フォーカスの位置が常に分かる（ペインは枠の色、行は選択色、入力欄はフォーカスリング）。マウスでクリックしたときとキーで移動したときで見た目を変えない | P1 |
| FR-KB4 | マウスでしかできない操作を作らない。ドラッグ操作（区切り線・ペイン移動・並べ替え）には必ずキーの代替を用意する | P1 |
| FR-KB5 | 単キーの操作は、文字入力欄にフォーカスが無いときだけ効く。修飾キーは Ctrl / Shift / Alt を使い、JIS 配列で位置が変わる記号キー（`\` `@` `[` `:` など）と、Windows・Electron の既定と衝突するキーは使わない | P1 |
| FR-KB6 | キーの割り当ては設定で変更でき、衝突を検出して知らせる。既定に戻せる | P1 |
| FR-KB7 | **F1** でショートカット一覧を重ねて表示する（いまフォーカスしているペインで効くキーを先に出す）。メニュー・ツールチップ・コマンドバーの候補にも割り当てたキーを出す | P1 |
| FR-KB8 | E2E テストに、マウスを一切使わず「起動 → 更新 → ウォッチリストをめくる → スクリーニング → 結果をウォッチリストに追加 → レイアウト切り替え」を通すシナリオを置く | P1 |

## 8. アーキテクチャ

### 8.1 プロセス構成

```
┌ renderer（UI: Svelte 5） ─────────────────────────────┐
│ Layout ─ PaneHost ─ WidgetRegistry                   │
│ stores: layout / link groups / favorites / i18n / jobs│
└───────────────┬──────────────────────────────────────┘
                │ window.elecxstock（preload / contextBridge のみ）
┌ main（薄い） ───┴─────────────────────────────────────┐
│ ウィンドウ管理・単一インスタンス・メニュー                  │
│ IPC ルータ（zod で入力検証）→ Core へ中継                 │
└───────────────┬──────────────────────────────────────┘
                │ MessagePort
┌ utilityProcess: core ──┴────────────────────────────┐
│ Core（Electron を import しない純 TS）                 │
│  ├ Repository（SQLite）/ UserStore（JSON）            │
│  ├ JobQueue + RateLimiter                            │
│  ├ Providers（JPX / Yahoo / …）                      │
│  ├ Calculators（調整・集計・指標）                     │
│  └ Screener（FieldDef 登録表）                        │
└─────────────────────────────────────────────────────┘
          ↑ 同じ Core を CLI からも使う（P3）
```

| ID | 要求 | 優先度 |
|---|---|---|
| NFR-A1 | Core は `src/core/` に置き、`electron` を import しない（lint で禁止）。単体テストは素の Node で動く | P1 |
| NFR-A2 | UI は `window.elecxstock` 以外の手段を持たない（`sandbox: true`、`contextIsolation: true`） | P1 |
| NFR-A3 | API の型・チャネル名・zod スキーマは `src/shared/` に一箇所で定義する | P1 |
| NFR-A4 | API は「要求/応答」と「購読」の 2 種類。購読はペインの生存期間に合わせて自動解除する | P1 |
| NFR-A5 | 大量データ（数千本の足）は型付き配列で渡すことを検討する | P2 |
| NFR-A6 | **コードはすべて本プロジェクトでオリジナルに書く**。elecdex（GPL-3.0）を含む既存プロジェクトのコードは写さず、設計の考え方（レイアウト木・リンク・ペインの寿命など）だけを参考にする | P1 |

## 9. 非機能要件

| ID | 要求 |
|---|---|
| NFR-P1 | 起動からレイアウト表示まで 3 秒以内 |
| NFR-P2 | ローカルにある銘柄のチャート切り替え 100ms 以内（日足 5 年 + 週・月の集計込み。10 年でも 150ms 以内） |
| NFR-P3 | 2,000 銘柄のスクリーニング 500ms 以内 |
| NFR-P4 | チャート 9 枚 + リスト 2 枚の画面で、スクロール・十字線が滑らか（60fps を大きく割らない） |
| NFR-P5 | 取得中も UI が固まらない |
| NFR-R1 | 取得の途中で落ちても DB が壊れない（トランザクション、WAL） |
| NFR-R2 | 一部銘柄の取得失敗が他銘柄の更新・表示を妨げない |
| NFR-R3 | プロバイダが取れなくなっても、既存データでの閲覧・スクリーニングは続けられ、原因がログに出る |
| NFR-D1 | データ容量の目安: 2,000 銘柄 × 日足 5 年 ≒ 250 万行・百数十 MB、10 年で倍（P1 で実測して記録） |
| NFR-S1 | 通信先はプロバイダの許可リストに限る。CSP で外部スクリプトを禁止 |
| NFR-S2 | API キー（P3 の J-Quants 等）は `safeStorage` で暗号化して保存 |
| NFR-O1 | ログを userData に日付ローテーションで残す |

### 9.1 商用プロダクト品質の基準

「個人の道具」ではなく、市販の業務ソフトと並べて遜色のない仕上がりを求める。

| ID | 要求 |
|---|---|
| NFR-Q1 | **一貫性**: 色・文字・余白・角・線の太さはデザイントークンだけから取り、ペインごとの独自の値を書かない。トークンの一覧と使い方を `docs/design-system.md` に置く |
| NFR-Q2 | **状態の網羅**: すべてのペイン・ダイアログ・入力に、通常・フォーカス・無効・読み込み中・空・エラーの見た目を定義する（FR-V11） |
| NFR-Q3 | **ちらつき・ずれがない**: データの読み込みや更新でレイアウトが動かない（領域を先に確保する）。数値の桁が変わっても列幅が揺れない |
| NFR-Q4 | **表示倍率**: Windows の表示スケール 100〜200%、倍率の違うモニタ間でウィンドウを動かしても、線・文字・チャートがにじまない（Canvas は devicePixelRatio に追従） |
| NFR-Q5 | **アクセシビリティ**: 文字と背景のコントラストは WCAG 2.2 AA 以上。上昇・下落は色だけでなく符号（+ / −）でも示す。主要な要素にアクセシブルな名前を付ける |
| NFR-Q6 | **文言**: 日英とも用語集（`docs/glossary.md`）に沿って統一する。エラーには「何が起きたか・どうすればよいか」を書く |
| NFR-Q7 | **応答**: 操作に 100ms 以内で反応し、1 秒を超える処理は進捗を出し、取り消せる |
| NFR-Q8 | **ウィンドウ**: 位置・大きさ・最大化・モニタを記憶し、モニタが外れたら見える位置に戻す。最小サイズを決め、それ以下でも崩れない |
| NFR-Q9 | **配布**: インストーラ（NSIS）、アンインストール時に利用者データを残すか尋ねる、自動アップデート（GitHub Releases、P2）。コード署名は公開時に検討 |
| NFR-Q10 | **見た目の回帰テスト**: 主要画面のスクリーンショットを基準画像と比べ、意図しない変化を検出する（§11） |
| NFR-Q11 | **クラッシュ**: renderer・utilityProcess が落ちても自動で立ち上げ直し、利用者のデータとレイアウトを失わない。原因はローカルのログに残す（外部送信はしない） |

## 11. テスト方針

- **単体（Vitest）**: 調整係数・週月集計・指標・利回り・スクリーナーの条件評価（お気に入り条件を含む）・レイアウト操作・レート制御・カタログのキー一致（FR-N6）。
- **結合**: Core + SQLite（一時ファイル）で、初回取得 → 差分 → 分割検知 → 再取得、保存期間の延長・短縮、全データ・銘柄指定の削除と取り直し（利用者のデータが残ること）。
- **E2E（Playwright `_electron`）**: プロバイダはローカルスタブ。言語切り替え、お気に入りの絞り込み、ウォッチリスト操作、チャートめくり、**マウスを使わない操作だけで一日の流れを通すシナリオ**（§6.5）。
- **見た目の回帰**: 主要なレイアウトプリセットを日英・ダーク/ライト・表示倍率 100%/150% で撮り、基準画像と比べる（§9.1）。
- **性能**: NFR-P2, P3 を固定のダミー DB で計測するテスト。
